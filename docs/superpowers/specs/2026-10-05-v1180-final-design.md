# v1.18.0 final — a newer default Xray, fastest / ping per subscription, Android cores kept current

Owner's asks, 2026-10-05, after testing v1.18.0-beta.1 ("it looks right, I tested"):

1. Raise the default core on Windows, macOS, Linux and the router, as Android's bundled one already is. Answer to
   "which version": 26.9.30, "if it is stable". Android cannot swap its core by hand: "can something be done so a
   user can update?"
2. ⚡ Fastest for ONE subscription, and pinging one subscription's configs. Answer: one-tap, like today's Auto.
3. Then the final tag and release, and a list of what is left for him to decide.

## 1. Default cores (desktop and router)

- `SUGGESTED.xray` 26.3.27 → **26.9.30**. XTLS has marked every release after 26.3.27 a pre-release; v2rayN 7.25.4
  (a stable release) and v2rayNG 2.3.10 ship 26.9.30. Every config shape this app writes must pass `xray run -test`
  on it in CI (below) before the tag.
- The **default target** of a core is the newer of GitHub's latest stable release and `SUGGESTED[core]`.
  `Downloader.download(core)` (first install, the Update button, the weekly updater) installs it and
  `latestVersion(core)` names it, so the weekly updater moves 26.3.27 to 26.9.30 and never below what is installed.
  Xray-PattN (latest stable 26.10.3, ⭐ 26.9.22) and sing-box (1.14.2, ⭐ 1.13.14) install what they install today.
- **ECH on an old core**: a config with `echConfigList` on the official Xray older than 25.8.3 (`echSockopt`
  arrived there; `echConfigList` in 25.7.26) runs on Xray-PattN when it is installed (one log line), otherwise the
  connect is refused with a plain message — update Xray in Required files — like the finalmask case. The router's
  opkg feed fallback (24.12.31 / 25.1.30) is the case this catches.
- **CI gate**: a `test.yml` job downloads the ⭐ Xray, Xray-PattN and sing-box (versions read from coreVersions.js,
  linux-64) and runs `scripts/validate-configs.js`, extended with the v1.18 forms: ECH (udp / https / base64, under
  TUN with `echSockopt`, under the strict guard as DoH), pcs / vcn, pqv, Hysteria2 (salamander, port hopping, up/down)
  and mKCP header/seed through `coreCompat.adaptForCore` with the core's own version, Shadowsocks plugins.

## 2. Android

- Android 10+ refuses to `exec` a file an app downloaded into its own storage (W^X on app data); the cores have to be
  inside the APK (libv2ray in-process, sing-box and Xray-PattN as `lib*.so`). v2rayNG lives with the same limit: its
  core is updated by updating the app. So the APK carries the desktop's defaults: **libv2ray v26.9.30** (from
  v26.7.11) and **Xray-PattN v26.10.3** (from v26.9.13); sing-box stays 1.13.14 (the ⭐).
- **Update notice**: at most once a day the app asks GitHub's `releases/latest`; a newer version shows a card
  "IRNetFree vX is out — Download" that opens the release's APK. Settings lists the bundled core versions.
- Installing a new APK over the old one needs the same signature — the permanent key's four GitHub secrets (owner).

## 3. Fastest and ping per subscription (desktop, the router's web UI, Android)

- Servers list: every group with two or more configs (each subscription, and "added by hand") gets two header
  buttons: 📶 test this group (TCP + real delay, as Ping all does) and ⚡ connect to this group's fastest.
- Home picker: under ⚡ Auto, one row per subscription, "⚡ Fastest — <name>", when there are two or more groups.
- A group's ⚡ tests the group again unless all of it was tested in the last 3 minutes, then connects to the best —
  real delay first, the TCP handshake as the fallback (Auto's ranking). The global Auto is unchanged.
- Android: the group header gets the same two actions; ⚡ runs Fastest.kt (TCP shortlist, then real tests) on the
  group's servers only.
