# v1.13.5 — OpenWrt: no DNS through the WAN's own subnet; less work per packet

OpenWrt only; `src/main/tunSingbox.js` is untouched.

## The DNS leak

v1.13.3's main-first rule (8998) sends anything the main table routes by a
*specific* route out directly — and that includes the WAN's own subnet. When
the router sits behind an ISP modem, the resolver its WAN DHCP hands out is
usually that modem (192.168.0.1 or the like): a connected route. So every
query dnsmasq forwarded went straight to the modem, off the tunnel. That is
the leak a DNS-leak test shows.

The rule now reads `not dport 53 … lookup main suppress_prefixlength 0`: a
DNS query is never let out through a specific route; it falls through to
sing-box's rules, enters the tunnel and is answered by the core. (sing-tun's
own rule set carries the same `not dport 53`, for the same reason.) The QEMU
smoke asserts it: `ip route get <gateway> ipproto udp dport 53` → `IRNetFree`,
while port 123 to the same address stays on `br-lan`.

Two things this does not cover, by design: a client whose DNS is DoH/DoT to a
public resolver (encrypted, its own choice, goes through the tunnel), and the
in-country resolver of the `bypass-ir` routing mode (dialled direct on
purpose, for Iranian names only).

## Speed — what changed, what to expect

The path on a router is tun → sing-box → SOCKS over loopback → xray → TLS →
WAN: two user-space hops and three copies per packet on a 700 MHz Cortex-A7.
It is CPU-bound, and upload shows it first because the client-to-server
direction pays the tun read path per packet. Three things now cost less
(a fourth, GSO on the tun, sing-box ≥ 1.11 already does by itself on Linux —
the option that once asked for it is refused by 1.12, which CI found out):

- **No access log** on the router unless the log level is `info`/`debug`: one
  syslog line per connection, through the service's stdout, was real CPU.
- **Counters polled every 3 s** instead of every second.
- **QUIC (UDP 443) from the LAN is refused** — not dropped — so browsers fall
  back to TCP at once instead of pushing every Google and Apple flow through
  a proxy as UDP (the log was a wall of them). A switch in Settings → LAN,
  on by default on a router; devices that go direct keep their QUIC.

None of this can be measured in QEMU. On the device: run a speed test on a
phone, and `top` on the router meanwhile — if `sing-box` or `xray` sit at
100 % of a core, the ceiling is the CPU; if they idle, something else is
wrong and the log will say. `ip rule del` is now by preference, repeatedly,
so a rule left by an older version cannot survive a start.
