# v1.37.0 — connections, app by app

By the version rule: a new capability (a live view of every program's connections) — the second number.

## What the owner asked for

After reading github.com/babaktaremi/proxydog (per-app rules through library injection, macOS/Linux, TCP only):
two ideas worth taking — a config per app, and a live log of each app's connections. «اره هر دوتاشو بساز منتشر کن».
This release is the second; per-app configs follow in v1.38.0.

## How

No injection: every desktop sing-box TUN (Windows, Linux, macOS's compatibility backend — never the router,
tun2socks or the native macOS service) gets its loopback API (clash_api on 127.0.0.1, a fresh secret per connect)
and `route.find_process`, so every connection names its program. UDP and DNS included, Go programs too.

- src/main/connectionsWatch.js reads `/connections` while the view is open (every 1.5 s; reads within 700 ms share
  one answer), grouped by program: destination, TCP/UDP, the hotspot device it came from, bytes and live rate, age,
  the way it took (tunnel / direct / an outbound) and the rule; at most 200 per program. `close(id)` is
  `DELETE /connections/{id}`. When it cannot: not connected, not TUN, a backend without process names, the router.
- `conns:get` / `conns:close` in the desktop and the headless service; the preload and the router's web API bridge.
- A "Connections" tab beside the Logs (pro-only): programs as folding rows with their live rates, a filter, ✕ per
  connection; rows hold still while the pointer or focus is in the list. fa + en, RTL, 390 px.

## Proven

npm test (2837: connectionsWatch.test.js, connectionsUi.test.js); a real sing-box 1.14.4 on loopback named
node.exe as the process, answered DELETE with 204 and a wrong secret with 401; validate-configs runs the TUN config
with the API and find_process through `sing-box check`. A real TUN was not run (not allowed on the owner's PC).
