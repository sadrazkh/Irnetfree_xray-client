# v1.47.4 — Official Xray 26.11.9: the "chrome" fingerprint is Chrome 155

By the version rule: an improvement to what already exists, so the third number goes up. The suggested official Xray
moves from 26.10.31 to 26.11.9 on the desktop and the router, and the APK carries it. Xray-PattN stays at 26.11.1 and
sing-box at 1.14.3.

## What the owner asked

«اول xray رسمی اگر کاری لازمه بکن» (2026-11-16): do what the new official Xray needs first; patterniha's core comes
after.

## What 26.11.9 changes for this app

- **The fingerprint `chrome` is Chrome 155.** Xray 26.11.9 is built on uTLS a13c59f, where `HelloChrome_Auto` is
  `HelloChrome_155` (read in uTLS's `u_common.go` at that commit). The release calls it "untargeted by TSPU yet".
  Every config this app writes without a fingerprint of its own says `chrome` (`parser.js`), so the core version alone
  moves them; nothing in a config changes.
- `hellochrome_155` is also a new name of its own. The editor does not offer it: Xray-PattN 26.11.1, the suggested
  fork, does not know the name, and a config asking for it would not run there. With `chrome` it is not needed.
- A WireGuard endpoint whose name cannot be looked up gives up at the connection's deadline (XTLS/Xray-core#7323).
- An inbound that fails to start is closed and removed (#7223); Mux's writes to the underlying connection are
  serialised.
- Not written by this app, so nothing to do: finalRules' `blockDelay` renamed `delay` (#7329), Xray's own TUN on
  Windows (#7325, #7332, the WFP leak block), the XDRIVE (Google Drive) transport, the geo files as `.dat.gz`.

## Where it lands

- **Android:** the APK carries Xray 26.11.9 in place of 26.10.31 (AndroidLibXrayLite v26.11.9; its `go.mod` names
  xray-core 676eaf66, the "Xray-core v26.11.9" commit, and uTLS a13c59f).
- **Desktop and router:** 26.11.9 is the ⭐ in Required files, and a plain download or Update installs it (the newer of
  GitHub's latest stable and the ⭐). A core already installed is not replaced by itself: press Update for Xray under
  Required files.

## Tested

- CI's `cores` job hands every config shape this app writes to 26.11.9 (`xray run -test`) and runs the real-peer
  WireGuard probe and the other core probes with it; the version is read from `SUGGESTED`.
- `npm test`: the picker, the downloader and the version tests follow the new ⭐.
- Not run against a real server or on a phone. That Chrome 155 gets through where the previous hello did not is the
  release's claim, not measured here.

## Owed

Use it as usual. If a config that worked on 26.10.31 stops connecting on 26.11.9, Xray 26.10.31 can be picked again
under Required files, and the log of that moment is what the next round needs.
