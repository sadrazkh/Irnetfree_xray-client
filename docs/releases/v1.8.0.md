# v1.8.0 — the Android app catches up with the desktop

The Windows and macOS clients are v1.7.6 with a new version number: nothing
under `src/` changed (`npm test` 788/788). This release is the Android app,
which had stood still since Phase B while the desktop went through
v1.6.x–v1.7.6, and which by now was not merely behind but broken on the
current cores.

## What was wrong

- **Every server with `allowInsecure=1` refused to start.** The cores the app
  bundles reject `tlsSettings.allowInsecure: true` at config load ("removed
  and migrated to pinnedPeerCertSha256"), and most Iranian share links carry
  that flag. The desktop moved to certificate pinning in v1.7.0; Android still
  emitted the flag.
- **A WireGuard endpoint given as a name could panic the core** when the
  phone's resolver answered nonsense — the same fake-IP network the desktop
  met in v1.7.3 (every name answered from 198.18.0.0/15). The desktop resolves
  the endpoint itself since v1.7.3; Android left it to the core.
- **No geo files.** `geoip.dat`/`geosite.dat` were never bundled, so "Bypass
  Iran", "Bypass China" and "Block ads" were inert, and any config naming a
  `geosite:` rule failed to load.
- **DNS was the pre-v1.6 shape**: one resolver list, no port-53 hijack, no
  in-country resolver pinned to Iranian domains, no per-port direct rules —
  the plan the desktop has had since the managed-DNS work, with the v1.7.2
  fixes on top.
- **The corporate chain did not work the way it does on the desktop**: no
  `dns=` on WireGuard records, so the company resolver was never asked through
  the tunnel; `AllowedIPs` were not widened around it; the address kept its
  `/24`.
- Smaller: xhttp `extra` was dropped on import; `bufferSize: 0` was still set
  on every plan with a WireGuard hop (the v1.7.2 finding); `freedom` dialled
  with `UseIP`.

## What changed (`android/`)

| Area | Files | What |
|---|---|---|
| managed DNS | `core/DnsPlan.kt` (new), `core/ConfigBuilder.kt`, `core/SingboxConfig.kt` | a line-for-line port of the desktop's `dnsBuilder.js`: DoH through the exit, the in-country resolver with `expectedIPs` + `skipFallback`, the `dns-out` hijack of port 53, direct rules per resolver port, target resolvers asked through their own outbound; `routing.domainStrategy` follows `dnsManaged` |
| certificate pinning | `core/CertPin.kt` (new), `ConfigBuilder.applyCertPin`, `vpn/XrayVpnService.ensureCertPins` | pin on first use (the leaf certificate's SHA-256, stored on the record as `certPin`/`certPinAt`), re-checked every 6 h; `allowInsecure` is never written into a config again |
| endpoint resolution | `core/TrustedDns.kt` (new), `XrayVpnService.resolveWgEndpoints` | OS lookup first; when every answer is in a range no public server can be in, a DoH JSON query to a literal-IP resolver; the address is substituted into the peer endpoint before the core starts, and the log says which source answered |
| corporate WireGuard | `core/LinkParser.kt`, `core/ConfigBuilder.kt`, `core/ServerEditor.kt`, `core/Models.kt` | `dns=` on links, the manual form and the editor (`ServerConfig.dns`/`dnsDomains`); the resolver asked through the chain with `skipFallback` when search domains exist; `widenWgAllowedIps`; `/32` address; a real `wireguard://` share link |
| advanced routing | `core/ConfigBuilder.kt` (`modeBypassRules`) | `advancedUseMode`: the simple bypass mode under the user's rules, in the desktop's order; the exit carrier skips a split-tunnel WireGuard |
| geo data | `scripts/fetch-libs.sh`, `vpn/XrayCore.prepareAssets`, `app/build.gradle.kts` | `geoip.dat` + `geosite.dat` (Loyalsoldier `202609152354`, 17.1 MB + 11.0 MB) fetched into `assets/`, copied beside the core at connect time; **the release APK went from 70.1 MB to 89.9 MB** (the packager stores the 28 MB of data deflated) |
| settings | `core/Models.kt` | `dnsManaged`, `dnsRemote`, `dnsDirect`, `advancedUseMode`; a store from an older APK migrates its `dns` list the way the desktop's `settingsMigrate.js` does |
| parity details | `core/LinkParser.kt`, `core/ConfigBuilder.kt` | xhttp `extra` kept and written back; no `bufferSize: 0`; `freedom` on `UseIPv4` unless IPv6 is on |

## UI

Settings gains **DNS managed by the app** with the remote (DoH) and direct
(in-country) resolver lists; Routing gains **Apply the routing mode (Bypass
Iran/China) under these rules**; the WireGuard sheet and the config editor
gain the DNS line; the editor's "Allow insecure" is now labelled for what it
does: pin the server's certificate on first use.

The Android UI is still English — `MainActivity.kt` was English-only before
this release, and localizing it is a separate piece of work.

## Tests and CI

The pure core now has JUnit tests that run on the JVM without a device or an
emulator: 41 tests in `DnsPlanTest`, `ConfigBuilderTest`, `LinkParserTest`
and `TrustedDnsTest`, each a transcription of the desktop's own assertions
(`tests/dnsBuilder.test.js`, `configBuilder.test.js`, `parser.test.js`,
`trustedDns.test.js`), so the two clients are held to the same rule order and
the same resolver plan. `test.yml` runs them after `assembleDebug` on every
push and fails if no test executed. Nobody working on this repo can compile
Kotlin locally, so the first green run (Tests #64) is the only compile that
has happened.

## What this release cannot claim

No Android device was in the loop. The config and the DNS plan are verified
against the desktop's pins; the tunnel, the pin probe over a real TLS
handshake, the endpoint substitution on a hostile network and the geo copy on
first connect need a device: with "Bypass Iran" a `.ir` site should resolve
through the domestic resolver (the log at `debug` shows `dns-internal` →
`178.22.122.100` direct) and everything else through DoH; `nslookup` from a
terminal app should be answered (the hijack); the corporate chain should bring
up company sites.
