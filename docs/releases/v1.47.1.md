# v1.47.1 — Android: fewer crashes, fewer jumps, a tunnel that comes back

By the version rule: fixes and improvements to what already exists, so the third number goes up. Android only: the
desktop and the router are the same code as v1.47.0.

## What the owner asked

«نسخه اندرویید خیلی پرش و کرش داره اینو درست کن وبهینش کن هم تو اتصال هم قطع نشه هم مصرف باتری».

No phone log came with it, so everything below was found by reading the code: two rounds of parallel reviews, each
finding confirmed against the source before it was fixed. **Nothing here has run on a phone.**

## Crashes: what could end the process

- **Background work that fails is logged, not fatal.** The app's background scope had no exception handler, so an error
  in a test, in "fastest" or in a subscription fetch ended the process, and the tunnel with it.
- **A test no longer shares the tunnel's process** while a tunnel is up: it runs on the PattN subprocess where that is
  bundled, so a Go panic in a throwaway core cannot abort the live one (limit: KI-040).
- **Memory:** a subscription body stops at 16 MB and an IP-info answer at 1 MB; the log writer reads at most the last
  256 KB of its file and survives an `OutOfMemoryError`.
- **Smaller ones:** another app's intent is read inside a guard; a config too large for the clipboard says so; a pool or
  chain row writes by id, not by the index it was drawn with; the Quick Settings tile guards its store.

## Jumps: what made the screen stutter or jump

- **Home no longer redraws twice a second.** Traffic and uptime tick in their own small parts; the ring's pulse is read
  while drawing and exists only while connected.
- **The Servers list is built only when what it shows changes.** Every result of every test used to rebuild and sort
  all groups; now each row reads its own result, and the list opens at the server in use without a jump.
- **Screens redraw instead of being rebuilt.** Picking a server or saving a setting used to rebuild the whole screen:
  lists lost their scroll, the search and the open row. Every store write now moves one counter the screens read.
- **Heavy work left the main thread:** a subscription refresh's merge and save, parsing pasted links, the per-app list.
- **Ports are saved when typed out** (KI-041): the pool's port field snapped back to the old number while typing. Pool
  and Settings ports save 1 to 65535 when editing ends; an empty pool HTTP port means no HTTP listener.
- A baseline profile compiles the UI ahead of time on release builds.

## Drops: a tunnel that died under "Connected"

- **An idle TCP connection is no longer cut after a minute.** The one hev key we wrote was the idle limit for TCP as
  well as UDP; TCP now has 300 s.
- **The watchdog adds suspicion up over four ticks**, so a dead tunnel under light use is asked about; a light tick that
  was itself answered is no step towards an ask; with no network at all nothing is asked.
- **The asks wait out a full uplink** (15 s instead of 6 s) and the second goes to another host, so an upload or an exit
  that cannot reach one page no longer causes a rebuild.
- **A move off a network that lost its internet rebuilds at once**, and only when that network was seen with internet.
- **A rebuild never moves the tunnel** to a row that was only tapped, or applies settings waiting for Apply.
- **A subprocess core that dies for good** has the whole connection rebuilt, once per five minutes, instead of ending
  the session on its second death.

### A rebuild that fails

A rebuild is a connect nobody tapped: after a change of network, a stall, a group reload. One that failed used to end
the VPN, and in the first version of this round retried for good with the TUN closed, so every app went out around the
VPN behind a notification that only said it was trying.

| Failure | What happens | Internet meanwhile |
|---|---|---|
| 1st, 2nd, 3rd | Tried again in 30 s, 60 s, 120 s; phone kept awake | Waits for the VPN (the TUN is held) |
| 4th, always-on VPN off | The session ends: error on screen and in a notification | Back to direct, said |
| 4th, always-on VPN on | The TUN is let go; tried again every 120 s; one notification | Direct, or blocked where "Block connections without VPN" is on |

What no wait makes better ends a rebuild at once: a config no core here runs, a VPN interface Android refuses. A
Disconnect, or the notification's Stop, ends any of it. The service is also no longer stopped under a rebuild that is
still being prepared, which left a tunnel up with no notification and nothing to stop it with.

## Battery

- **No access log unless the log level is info or debug:** one line per connection was written with the screen off.
- **The exit lookup waits for somebody to look:** a rebuild nobody saw made up to two HTTPS fetches for a line on Home.
- **One wake lock, bounded:** held while a change of network or a rebuild is dealt with (45 s at most, or one retry
  wait), and let go by every teardown.
- **A card on Home** says, once, how to exempt the app from battery optimisation, so that Android is less likely to
  stop the tunnel in the background.

## Limits

- A failed rebuild holds internet back for up to three and a half minutes of waits before it gives up (KI-042).
- Under always-on, the retries after the fourth failure hold no wake lock: a sleeping phone tries again when it wakes.
- A TCP connection idle for five minutes is still cut; a dead far end that answers a little may not be noticed under
  light use (KI-043).
- UI findings read and left: KI-044.
