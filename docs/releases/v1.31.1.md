# v1.31.1 — the suggested cores move to the security release (Xray 26.10.21, Xray-PattN 26.10.22)

By the version rule: a fix of what exists — the third number.

## Why

XTLS withdrew Xray 26.10.10 and 26.10.17 on 2026-10-21 (their release pages are gone) and made 26.10.21 the latest
stable, as an emergency security update: the private keys of eight intermediate certificates (India) were cracked, and
the root store the core carries since 26.10.10 (#7105, it checks certificates against its own roots, not the OS's)
still trusted their three roots. 26.10.21 removes them (#7212) and is built with Go 1.27.3, which filters the bad
certificates even where the OS store is old. patterniha/Xray-core 26.10.22 carries the same change on top of 26.10.19.

26.10.10 was this app's suggested Xray and 26.10.13 its suggested fork; the APK carried both.

## What changes

- `SUGGESTED.xray` 26.10.21, `SUGGESTED['xray-pattn']` 26.10.22 (src/main/coreVersions.js) — what a first install,
  Update and the weekly updater install, what the version picker stars, what CI verifies every config shape on.
- Android: the APK carries libv2ray 26.10.21 and Xray-PattN 26.10.22 (android/scripts/fetch-libs.sh).
- The picker tests' release fixture: its newest Xray and fork rows renamed to the new suggested ones, every scenario as
  it was.

## Good to know

- A desktop or router that ran v1.31.0 already moves on its own: GitHub's latest stable (26.10.21 / 26.10.22) is newer
  than v1.31.0's suggested versions, so Update and the weekly updater installed them already. The phone needs this APK.
- The features that need "26.10.10 or newer" (a WARP account on MASQUE, the ECH outbound, useSystemCA) keep that
  wording — 26.10.21 has them all.

## Proven

CI on the new cores: every config shape through `xray run -test`, the real-peer WireGuard, WARP, group and MASQUE
probes, and the ECH outbound probe on the real network (sni=encrypted with it, no key without).
