# v1.16.3 — Windows tells you why; Android releases get one permanent signature

The owner reported that one Windows PC (of several) still leaks DNS and that its advanced routing to the corporate
WireGuard chain does not work properly, while another PC is fine; and that some Android phones refuse the install with
"App not installed as package appears to be invalid". The router is not touched in this release.

## Windows

Nothing here changes a generated config, a route, a DNS setting or the connect itself (the desktop's configs are pinned
byte for byte by tests). Each message appears only on a PC where its condition is true:

- **The leak guard failed** — shown in the window with the reason (it used to be only in the log).
- **Proxy only** — when TUN mode is on but the tunnel did not start, a lasting line on Home says so, with the reason
  (a missing sing-box or wintun, the sing-box error).
- **A WireGuard identity stored twice** — when the WireGuard record a connection uses shares its private key or its tunnel
  address with another stored record: a WireGuard server accepts one device per key, so the same peer used on two devices
  (or tested while connected) makes one of them stall. The notice says which record to keep — a record from a subscription
  comes back on its next update, so the hand-made copy is the one to delete.
- **Your local network inside a routed range** — when one of this PC's own subnets lies inside a range advanced routing
  sends to a chain (and the tunnel is up), hosts in it stay on the LAN; the notice names the subnet and the range.
- **Managed DNS off with a corporate resolver** — the existing warning is now shown in the window too.
- **An old copy at logon** — when Windows starts a different IRNetFree executable at logon, a notice offers to point the
  logon task at this one (the only write, and only on your click).
- The banners now always stay on screen (they could be pushed out of view), long Persian notices are no longer cut off,
  the "DNS held" banner disappears once a connection is up — and "give my internet back" refuses while a tunnel uses the
  guard (it would have put the adapters back on the ISP's resolvers under a live tunnel). A connect that fails before a
  tunnel comes up gives back DNS held by a given-up reconnect.

## Android

- Every release so far was signed with a throwaway key made fresh on the build server, so each version carried a
  different certificate and a phone with an older copy refused the update ("package appears to be invalid"); phones
  without the app installed it fine. The build now uses one permanent release key as soon as it is configured, refuses to
  publish a debug-signed APK when it is, and checks the APK's certificate before publishing.
- **This APK is still signed with a temporary key** (the permanent key is not configured on the build server yet). On a
  phone that refuses it: copy your subscription link, uninstall IRNetFree (and IRNetFree Plus, in every profile), then
  install. The first release with the permanent key will need that once more on every phone; after it, updates install
  in place.

## Check on your own devices
- On the Windows PC that leaks: connect and read the window — the notice that appears names the cause.
- Android: uninstall, install, re-add the subscription.
