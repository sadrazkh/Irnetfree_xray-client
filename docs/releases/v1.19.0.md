# v1.19.0 — JSON configs and JSON subscriptions

## What the owner asked for

"Support JSON for links or subscriptions like this one — it must support everything." His example subscription
answers this app with an array of 40 complete Xray configs: 38 vless/ws/tls servers and two info rows (expiry, data
left). Until this version the app could read none of it.

This is the first of three parts he asked for. The other two follow next: several saved advanced routings with chains
built on a shared base config and a picture of where traffic goes, then sharing them as one link.

## Every platform (Windows, macOS, Linux, the router, Android)

- **Xray JSON is read**:
  - one config, an array of them, or the same base64-encoded;
  - pasted into the add box, or answered by a subscription.
- **Each config becomes a server.**
  - Its name is `remarks`.
  - Its main outbound is the one the config's own catch-all routing rule uses (else `proxy`, else the first proxy).
  - The outbounds it dials through — a fragment/noise `freedom`, the hops of a chain — are kept verbatim as its helpers.
  - A balancer becomes one server per member.
  - Info rows such as "📅 expiry" or "📦 data left" are not servers.
- **sing-box JSON is read** too.
  - Its vless, vmess, trojan, shadowsocks, hysteria2, wireguard, socks and http outbounds become ordinary servers.
  - A `detour` is named in the server's name; ECH from `tls.ech.config` is kept.
  - Unsupported types are listed by name.
- **Clash YAML** is answered with "Clash YAML is not supported — use the subscription link".

## Full and raw

- **Full (the default).** The server is part of the app:
  - ping, ⚡/📶, chains, advanced routing, TUN, managed DNS, the leak guard and mux all apply;
  - its helpers are written next to it under their own tags (`<tag>~<helper>`), so two JSON servers never collide;
  - a JSON chain is entered at its first proxy hop — the leak guard's holes and the TUN bypass are cut for that address.

  The config's own routing, DNS and inbounds give way to the app's, and the edit view lists what they were.
- **Raw (per server).** The config runs exactly as written, with its own routing and DNS:
  - its inbounds are replaced by the app's;
  - `allowInsecure`, which current cores refuse, is removed (a learnt certificate pin takes its place);
  - `proxySettings`, which Xray 26 refuses, is written as the `dialerProxy` it was migrated to.

  Raw runs in **proxy mode on Windows, macOS and Linux**. Under TUN, on the router and on Android, the full form runs:
  a config run as written would leave the TUN without the app's DNS answer and the server's own name without a
  resolver outside the tunnel.

## The UI

- A `JSON` badge on the card.
- The edit view:
  - the Full/Raw switch with its line;
  - what full mode does not use;
  - the config itself in an editor that checks it on save;
  - Copy JSON.
- QR shows the JSON when it fits (1,700 bytes, at least 2 px a module).
- Every QR is drawn at its intended 320 px now: an old CSS rule had held it at 232 px.

## Subscriptions

A JSON subscription refreshes like a link subscription:
- same ids;
- your rename, raw/full choice and edited config are kept;
- the provider's text stays the server's identity, so an edit never makes a refresh duplicate it.

## Router installer

`install.sh` asks again (three tries) when the OpenWrt mirror drops a package download. The CI emulator met it on a
different package every run since 2026-10-08.

## Unchanged

Links, link subscriptions, and every config, share link and sing-box translation of an existing server: checked over
166 cases, byte-identical to v1.18.0.

## Check on your own devices

- Add the JSON subscription link: 38 servers, no "expiry" or "data left" rows.
- Connect one in Full (TUN and proxy), then switch it to Raw in proxy mode.
- Copy JSON / QR of one.
- On Android, the same subscription and one connect.
