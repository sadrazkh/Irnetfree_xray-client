# v1.10.1 — Android: choosing a config no longer moves the list, and the actions open only when you ask

Android only. Nothing in `src/` changed (`npm test` 796/796).

v1.10.0 brought the config list to design 2c but got three things wrong about
how it behaves under a thumb.

## The list jumped to the top

Picking a config near the bottom scrolled the list back to the beginning.
Selecting called `bump()`, and `bump()` increments `rev`, which `key(rev)` in
`App` uses to rebuild the whole screen — taking `rememberScrollState` with it.

Selection is now mirrored in the screen's own state: the store is still
written, but only the two rows that changed repaint. The list does not move.

## The card opened by itself

One tap both selected a config *and* unfolded its metrics and five actions, so
simply choosing something re-flowed the list under your finger.

The two are separate now:

- **Tap a row → it is in use.** Same height, same place; the border, the fill
  and the badge are all that change.
- **Tap it again, or tap the chevron → the actions open** (test, copy, QR,
  edit, delete, and the three measurements). The chevron opens any row without
  changing which config is in use.

Nothing is open when the list first appears.

## IN USE was only visible when the card was open

It now sits beside the name whether the row is open or closed, which is where
the design puts it and the only place it reads at a glance.

And a selected row is unmistakable: a full mint border at 1.5dp and the
selected fill, rather than the dim border v1.10.0 used.
