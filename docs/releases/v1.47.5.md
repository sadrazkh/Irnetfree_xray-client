By the version rule: fixes to what already exists, so the third number goes up. Android only; the desktop and the
router are unchanged.

## Per-app routing

- **No red verdict on a working tunnel.** Under "Only these apps", twelve seconds after a connect with none of the
  chosen apps open, Home said "Apps aren't reaching the tunnel". An empty TUN means that only on the whole device; here
  it is one line in the log (`TunnelSetup.carry`).
- **The app picker lists every app.** It stopped at 150 without a word, in plain string order — every lowercase and
  every Persian label after all the Latin capitals, so the Iranian banks and messengers people most want to leave out
  were the ones cut. Now the ticked apps come first, the rest a page at a time with "Show N more apps", in the order a
  person reads them (`PerAppList`).
- **A ticked app that is gone can be unticked.** It was never listed, and Home still counted it ("only 2 apps" while
  the whole device went through). It shows as "not on this phone"; Home counts the apps the phone has.
- Settings says that Android's own services without an app icon (Google Play services, the download manager) are not
  in the list, so under "Only these apps" they stay outside the VPN.

## Crashes and configs that could not run

- **A NaN in a link's JSON.** [A] Android's org.json reads `NaN`, `Infinity` or `1e999` inside an array and then
  cannot write it back: the save was `putString("servers", null)`, which removes the key — every server gone at the
  next launch. Such JSON (`fm=`, `extra=`, the ECH outbound, a vmess body, an imported config) is refused where it
  comes in, and the store never writes what it cannot write (`JsonSafe`, `Store.putJson`).
- **JSON nested thousands deep in one link** ran the thread out of stack and stopped the whole subscription refresh.
  It is that line's error now.
- **The VPN permission dialog missing** (a ROM without it) ended the app on the first Connect; now a message says so.
- **IP and port rule values** went into the config as typed: `google.com` in an IP rule (changing a rule's type keeps
  its value) made Xray refuse the whole config. Such a value is left out, shown in red in the rule editor and named in
  the log at connect (`RuleValues`).
- **A chain whose server a refresh dropped** connected one hop short, leaving at the wrong exit. It does not connect
  now, and says which chain to fix.
- **Two servers under one id** in a big subscription (16 random bits a millisecond): tapping one connected the other,
  a delete took both. Ids have 32 bits and a counter; a duplicate already stored gets a new id at start.
- **A port above 65535** in a link refuses that line, not the group or profile it is in.

## Smaller

Subscription URLs (their path is the panel's token) are no longer written to the log people share; opening the app
from Recents no longer asks about the link that first opened it; Check IP asks through the running tunnel's port;
text shared as styled text is read; one bad element in a stored list no longer loses the rest; the subscription fetch
reads the server lists on the main thread; split screen and folding no longer send the app back to Home; an edit
sheet open during a refresh keeps what the refresh changed; the proxy sheet refuses a port outside 1 to 65535.

## Tested

- New JVM tests: `PerAppListTest`, `JsonSafeTest`, `RuleValuesTest`, `NewIdTest`, and additions to
  `TunnelSetupTest`, `ConfigBuilderTest`, `LinkParserValuesTest`, `ServerEditorTest`. Written without a JDK on the
  machine; CI's `android` job is their first run.
- The NaN path cannot run on the JVM (its org.json refuses NaN outright); it was read in code, not seen on a phone.
- Nothing ran on a phone.
