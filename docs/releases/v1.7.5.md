# v1.7.5 — country flags on Windows too

A flag emoji is not a character. `flagEmoji()` turns an ISO-2 country code into
the two Regional Indicator letters the standard prescribes (GB → U+1F1EC
U+1F1E7) and the **font** is what ligates them into a flag. Apple Color Emoji
does it, Noto Color Emoji does it, and Microsoft's Segoe UI Emoji deliberately
carries no national flags at all — so the egress-IP readout and the server
rows showed a flag on macOS and the bare letters "GB" on Windows.

This release bundles `src/renderer/vendor/TwemojiCountryFlags.woff2` (78 KB, a
COLRv1 font holding those ligatures and nothing else), declares it in
`styles.css` with `unicode-range: U+1F1E6-1F1FF`, and names it first in both
type tokens. Because the range is limited to the regional-indicator block, the
font is consulted for those code points only: Latin, Persian, the monospaced
figures and every other emoji still come from the same fonts as before —
measured identical to the character, with and without the family in the stack.

Verified in the app's own page on Windows: the flags render (🇬🇧 🇮🇷 🇺🇸 🇩🇪 🇳🇱),
a control line forced to Segoe UI Emoji beside them still shows the boxed
letters, and each flag measures one em-square glyph instead of two letters.

The artwork is Twemoji under CC-BY 4.0; the attribution, the source package and
the font's own sha256 are recorded in
`src/renderer/vendor/LICENSE-TwemojiCountryFlags.txt`, and a test fails if the
file's bytes ever stop matching what that file claims. `*.woff2` is marked
binary in `.gitattributes` so no checkout can convert it.

Nothing outside the renderer changed. Native menus (the tray) are drawn by the
OS and do not use flags. `npm test` 787/787, `npm run validate` 183/183 on the
official core.
