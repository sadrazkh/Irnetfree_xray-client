# v1.11.0 — Android: connect on open

Android only. Nothing in `src/` changed (`npm test` 796/796), and nothing else
in the app changed either — this adds one setting.

## The setting

**Settings → Connect on open.** Off by default. With it on, opening the app
connects to the config in use, the way the desktop connects to the last server
on launch (`main.js`, `autoConnect`).

It runs **once per process**, not once per screen: the check lives in the app
shell, which recomposes whenever a tab changes or a setting is saved, so a flag
that dies with the process is what "on open" actually means.

Three things stop it:

- **Nothing to connect to.** The selection is resolved through `buildPlan()`
  first, which is what fails when the config it names has been deleted or a
  chain has lost a member — the desktop makes the same check. The reason goes
  to the log.
- **VPN permission not granted yet.** Android asks for consent through a system
  dialog, and throwing one at somebody who has just opened the app — maybe only
  to paste a config — is not auto-connecting, it is ambushing them. The attempt
  is skipped with a log line saying so; one manual connect grants it for good,
  and every launch after that is silent.
- **Already connected**, checked before and after the short wait.

The wait is 700ms, so the first frame is drawn before a foreground service and
a core start competing with it.

`EngineChoiceTest` pins that the setting is off in a store that predates it —
an upgrade must never start a tunnel on its own — and that it survives a
restart in both directions.
