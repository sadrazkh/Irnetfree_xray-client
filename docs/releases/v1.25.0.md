# v1.25.0 — MASQUE, and WARP over MASQUE

## What the owner asked for

"Has the new Xray core added anything useful — a protocol?" It had: MASQUE (IETF CONNECT-IP, RFC 9484), a whole IP
tunnel over HTTP/3 or HTTP/2, and since Xray 26.10.10 Cloudflare WARP over it — the protocol the official WARP app
uses now, which looks like ordinary HTTPS where WARP's WireGuard is easily blocked. A sample was approved with three
choices: the app signs up for WARP itself, one HTTP/3 and one HTTP/2 server by default, and MASQUE servers are shared
as JSON (no client has a share link for it; four ad-hoc `masque://` forms exist and none agree). The owner then asked
about domain fronting, and the WARP window got an optional cover domain.

## What it does

- **MASQUE is a protocol of its own** in the server editor (Simple and Pro), in «+ دستی» / + Manual, on Android.
  - **HTTP/3** (QUIC, UDP 443) or **HTTP/2** (TCP 443, for networks where QUIC is blocked).
  - A user and password for your own MASQUE server; path, Host and headers in the Pro view.
  - TLS only: SNI, fingerprint (HTTP/2), a certificate pin or a name to check it by, ECH.
  - Anti-DPI by version: noise before QUIC, a fragment of the TLS hello over HTTP/2.
- **«+ WARP»**: one window that makes WARP servers.
  - **A new account**: the app makes the device key on this computer, registers it with Cloudflare, enrolls the key
    for MASQUE and switches WARP on. Directly, or through the app's own connection when Cloudflare's sign-up is
    blocked. A WARP+ key is optional. The window states that signing up accepts Cloudflare's terms.
  - **An account you have**: usque's `config.json`, or an Xray WARP-MASQUE outbound.
  - HTTP/3, HTTP/2 or both (the default: two servers, «تست همه» / Test all tells which is better here); the endpoint
    automatic, IPv6, or a clean IP of your own; anti-DPI on.
  - **A cover domain**: the SNI is a site of your choice behind Cloudflare (a whitelisted one, say), and the
    certificate is checked by that site's name. The IP is still WARP's own — Cloudflare's ordinary website IPs do not
    serve WARP.
- **Sharing a MASQUE server** copies one line of JSON (QR the same). Pasting it into IRNetFree gives back an editable
  MASQUE server; a full JSON config with a MASQUE outbound (a 3x-ui JSON subscription, say) becomes a JSON server
  instead of being dropped, as it was before.
- **Every TLS protocol** gets «گواهی‌های سیستم‌عامل هم معتبر باشند» / useSystemCA: since Xray 26.10.10 a certificate
  is checked against the core's own roots, not the system's; this is for a server whose certificate comes from a
  private CA installed on the system.

## Underneath

- The record is native (like Hysteria2), not a JSON server, so the editor's every field reads and writes it; its
  `raw` is the share JSON.
- MASQUE never takes Mux, never runs on sing-box (the connect runs it on Xray, or on Xray-PattN when chosen), never
  writes allowInsecure or REALITY (the core refuses both).
- **A core too old says so**: MASQUE needs Xray 26.9.30, a WARP account 26.10.10. The connect is refused with that
  reason and where to update, on the desktop and the router — the router's opkg fallback cores cannot run it at all.
- The TCP ping skips MASQUE over HTTP/3 (it is UDP), as for Hysteria2.
- The WARP sign-up: the API version and headers wgcf 2.3.0 moved to after Cloudflare's 429s, TLS 1.2 with
  http/1.1; one sign-up at a time; the options are checked before a device is registered; the token and the private
  key are never written to a log or an error.

## How it was verified

- **A real MASQUE server in CI** (`scripts/probe-masque.js`): Xray's own MASQUE inbound on loopback, the client
  config the app's builder writes for a server made from the editor's fields, on the suggested Xray 26.10.10 and
  Xray-PattN 26.10.13 — over HTTP/3 and HTTP/2: a page 10 of 10 times, IPv6 inside the tunnel, 2 MB in one piece,
  UDP 20 of 20, and a wrong password refused.
- **Every MASQUE config the app writes** goes through `xray run -test` on both cores: HTTP/3 and HTTP/2 with a user,
  a WARP account over both, behind a cover domain, with noise and with a fragment — each plain, under TUN and under
  the strict leak guard.
- **The WARP sign-up** against a local fake of Cloudflare's API: every request's shape, WARP switched on only when
  it was off, the WARP+ key, each error, the token and key never in a log; a guard makes any test that reaches
  `cloudflareclient.com` fail. Nothing here called the real API.
- The window, the editor and the cards: renderer tests and headless-Chrome screenshots. Android compiles in CI with
  its unit tests.

## Owed

- **A real sign-up and connect** (only the owner can): a new account directly and through the connection, HTTP/3 and
  HTTP/2 on a real network, a cover domain, a WARP+ key, the router's web UI, and Android on a phone.
