# v1.33.0 — extensions, and users with their own password, cap and config

By the version rule: two new capabilities — the second number.

## What the owner asked for

«برنامه رو ماژولار کنیم … شبیه اکستنش باشه بتونه طرف روی برنامه نصب بکنه یا نکنه» — then, for his own home and
office (also on a Windows hotspot): «یوزر به روتر وصل میشه بتونه با یوزر نیم پسورد و محدودیت حجمی مختلف یا حتی
کانفیگ های مختلف وصل بشه». Built-in extensions, not downloaded code (a VPN runs with admin/TUN rights; Android 10+
will not run downloaded code; GitHub is filtered). Built with six parallel agents against one contract.

## Extensions («افزونه‌ها») — desktop, router, Android

- An Extensions page: chains, groups, WARP/MASQUE (needs chains), proxy pool, advanced routing, ECH outbound,
  anti-DPI, LAN sharing, multi-internet, the router's remote relay, users. Install / Remove; "in use: N"; what a
  removal hides is said before it.
- Off hides every entry point of it (`data-module` + one CSS rule per extension on desktop/router; checks in the
  Compose screens on Android). Nothing is deleted: a chain, a group, a pool entry, a profile keeps working, and the
  item a picker has chosen stays in it. Multi-internet and users are inert when not installed.
- A store from before keeps every extension it uses (a one-time migration); a new install starts with all off.

## Users («کاربران») — desktop (incl. a Windows hotspot) and router

- Each user: username + password, a config of their own (the current connection, a server, a chain, a group,
  direct or block), a data cap per day or month, an expiry date, a device limit (router), on/off.
- **Proxy accounts** (desktop, Windows hotspot, router): one SOCKS5 + HTTP pair on the LAN; Xray names each session
  by its username (proxy/socks/protocol.go:165, proxy/http/server.go:127) — per-user routing and per-user bytes.
  Windows firewall rules for the two ports.
- **Transparent mode** (router): no settings on the devices. A device assigned to a user, or signed in on the
  router's own login page (a captive portal: http redirected to it, everything else held), rides its user's config;
  blocked devices and users over their cap get nothing. sing-box rule sets by source address (1.11–1.14), one Xray
  inbound per config, per-device counters in nft; caps count per device for its user.
- Windows hotspot: proxy accounts only (the hotspot's NAT hides which device a packet came from).

## Proven

- npm test: modules, modulesIpc, lanUsers{Model,Xray,Meter,Ipc,Ui,Router,RouterDevices,RouterNft,RouterPortal},
  lanUsersProbes; configs byte-identical with everything off (pinned).
- CI: the cores' `-test` over the users configs; `probe-lan-users` (two users on two servers through the proxy
  accounts, wrong password and a disabled user refused, per-user bytes); `probe-lan-portal` (a router in network
  namespaces with sing-box, nft and the portal: an assigned device, a login, a block, a cap).

## Not proven here

On the owner's router (AC-1304): the captive page on real phones and Windows, sing-box reloading the rule sets, the
nft counters with flow offloading. On Windows: the hotspot with proxy accounts and the firewall rules. Android:
the Extensions screen on a device.
