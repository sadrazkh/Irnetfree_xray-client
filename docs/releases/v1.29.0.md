# v1.29.0 — From the scan: groups that last without restarts, a fallback for them, Android that reads links and switches like the desktop

By the version rule: new capabilities (a group's fallback, the Quick Settings tile, the picker's search, the router's
tunnel watchdog) beside many fixes — the second number.

## What the owner asked for

At 05:40, a scan of the whole app for bugs, risky code and useful features; then «همنطوری که صلاح میدونی خودت پیش
ببر… با ایجنت های موازی… همشون». Four read-only reviews (desktop main, window, router, Android, plus a share-link
comparison) gave a verified list; the fixes were built in parallel worktrees and merged here. The Persian Android
interface and the Android port of the group set-aside were still being built when the owner asked for this release —
they come next.

## Groups (desktop and router)

- **A member set aside in the running core, without a restart.** The config carries the core's HandlerService on a
  loopback port when a group runs; a member the app sets aside is removed with `xray api rmo`, and put back with
  `xray api ado` (its outbound as built) — no connection drops, the corporate WireGuard on the base included. Proven on
  both cores (Xray 26.3.27, PattN 26.9.1): the same process; the silent member's probes — and the leak of a socket per
  failed TLS handshake — stopped; traffic through the others went on. Never the balancer's fallback member, never one
  the running config lacks; anything that cannot be done live falls back to the reload (groupLive.js).
- **A fallback of the group's own** (a WARP, say): `fallback: <server id>`, dialled as `T~fb` outside the members'
  prefix — never probed, never picked while a member answers — and the balancer's fallbackTag. The group editor offers
  it by subscription; without one, member 0 as before.
- **The reload, safe** (from the scan): built from the settings the live connection was built with (a pending port
  moved the core while the TUN forwarded to the old one); one at a time; never past a connect, a disconnect or a
  recovery; the reload flag a count (it could stick true); the router rebuilds a reload that left no core
  ('reload-failed') — before, the LAN sat behind a gateway forwarding into a closed port while the status said
  connected.
- **The evictor:** no dead streak while the whole group is down; back only after two answers 30 s apart; retests back
  off 3 → 24 min; a failed reload is asked again; kept across a reconnect of the same plan for 30 min.
- Editing a group the connection dials says "reconnect" ('groups'); the live meter counts a chain's hops and a base's
  own outbounds once (the corporate WireGuard read at twice its speed).

## Router

- The access log stays off after a reload (a line per LAN connection flooded the log ring).
- Geo files refresh between 03:00 and 05:00 under a live connection (a router connected around the clock never
  updated them) and the core reloads on them; cores never update under a live connection.
- LuCI: the token is readable by the write role only; a read-only login gets the status and a "needs write access".
- A tunnel watchdog: every 3 min, two misses a minute apart rebuild ('tunnel-stalled'), at most once per 10 min.

## Window (desktop and router web UI)

- A search-select's outside-click listener lives only while its menu is open (they piled up on every refresh).
- "Apply now?" only for a save that adds or changes a pending key (theme, skin, language no longer re-open it).
- WARP's first hop offers only what main's resolveHop accepts; a hop dragged onto another chain is ignored.
- Pile heads keep the scroll, take the keyboard, and a head that cannot fold writes nothing; titles translated;
  RTL-aware hop arrows; the Home picker has a search, search-selects take ↑/↓/Enter/Esc; the dead targetOptions is gone.

## Android

- **Share links read like the desktop:** a base64 subscription opening with `#profile-title:` or a blank line imported
  nothing; Shadowsocks plain `method:password` and `%3D` padding; `type=raw` with its HTTP header; IPv6 hosts bracketed
  (WireGuard endpoints, share links); vmess trailing data; a pasted WireGuard .conf; empty-value fallbacks; named errors.
- **A switch or a Reconnect never leaves the phone outside the VPN** (the old TUN is held until the new one is
  established); Reconnect is a connect onto the live tunnel.
- **A network watcher:** after Wi-Fi ↔ mobile data settles, a tunnel that answers neither of two asks is rebuilt (at
  most once a minute; callbacks only).
- The Apply bar names Mux and chain edits, and no longer the false "Per-app", "Advanced routing" or "Routing mode
  under the rules"; the pool resolves like the desktop (IPIfNonMatch); ⚡ fastest measures UDP-only servers through a
  throwaway core; a **Quick Settings tile**; always-on leaves a live tunnel alone; the log loses no line; sing-box's
  config file is per port.
