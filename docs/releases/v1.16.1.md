# v1.16.1 — The router's field round

The owner's first install of v1.16.0 on the AC-1304 found a "Gateway" nobody had explained, a LuCI «فعال» that did
nothing visible, and browsing that broke with a server's spoof switch on and half-loaded with it off. This release
fixes what the code showed to be wrong; what still depends on the router's own logs is listed at the end.

## Router (OpenWrt)

- **"Gateway" explained.** The router is the tunnel for the whole network: every device on its Wi-Fi or cable goes
  through the VPN with no setup on the device. The web UI now calls it "Whole-network tunnel" / «تونل کل شبکه», says
  it is a status and not an option, and the row opens the device list where a device can be sent direct. The desktop
  controls that mean nothing on a router (Proxy/TUN, leak guard, UDP block in proxy mode, the admin wording) are gone
  from the router's pages, and a missing sing-box is offered under Required files.
- **The LAN's DNS stays in the tunnel.** v1.16.0 took the in-country resolvers out of the tunnel for every device and
  every port: dnsmasq's upstream, or a phone using one of them (8.8.8.8 / 1.1.1.1 after a desktop backup), went out
  through the ISP in plain text and could get filtered answers. Now only the core's own direct lookups use them, out
  the WAN; the router's own lookups for remote access leave by the WAN too, and a bypass mode whose in-country DNS
  holds public anycast resolvers says so at every connect.
- **Patterniha servers run on Xray-PattN.** OpenWrt's own xray-core packages (24.12.31, 25.1.30) do not know
  `finalmask` and silently ran those servers without their mask. A `finalmask` server now goes to Xray-PattN first;
  without it the connect is refused with "This server needs Xray-PattN — install it under Settings → Required files".
- **An edit of the live server says it is not live yet.** Saving an edit of the server you are connected to (the
  spoof switch, a fragment, an address) did not change the running connection; now a toast says so with a Reconnect
  button, the pending list names it, and LuCI's Connect applies it instead of answering "already connected".
- **A connection the core refuses says why.** A config the core rejects used to be retried every 15-60 s with the
  reason only in the log. Now LuCI and the web UI show "Error: …", and the router tries again every 10 minutes, or at
  once on Connect; a config check killed by low memory is retried at the usual pace.
- **No retry storm.** A core that died before its port opened could restart the first attempt again and again; the
  backoff now holds.
- **Backups.** A desktop backup restored on the router no longer overwrites the router's own settings (TUN, kill
  switch, connect at start, QUIC refusal…); the router's own backup restores them all.
- **Hide SNI** is named for what it is (a TLS fragment), and on a server that already fragments with `finalmask` it
  says the second fragmenter is usually not needed.

## LuCI

- **«فعال» is honest.** Remote access refuses an Enabled that cannot work and says why, in Persian: enter the relay
  URL and token first, install cloudflared first, paste the Cloudflare token first. Changes there apply only with
  Save, and the page says so. The relay section explains that the relay is a server you run yourself.
- Refusals show where you look (and are logged), the Cloudflare state says "Enabled but not running: …", an install
  error is shown instead of an endless "Installing…", and the Overview has a "Whole-network tunnel" row.
- Packages are dated by their commit, so browsers and LuCI stop serving the old pages after an upgrade (log out of
  LuCI and press Ctrl+F5 once after installing this release).

## Also

- The relay closes every link when it stops (a link still waiting for its hello kept a shutdown pending).

## Good to know

- **Install Xray-PattN before you upgrade** if you use patterniha servers on the router (Settings → Required files in
  the web UI). Without it those servers are refused; with the kill switch on, the LAN stays blocked until then.
- **If pages still half-load**, send LuCI → Services → IRNetFree → Log → Copy diagnostics: the remaining DNS and spoof
  suspects (an old core, missing geo files, QUIC refusal turned off by a backup, the server itself not taking the
  fragment) can only be told apart from the router's own logs.
