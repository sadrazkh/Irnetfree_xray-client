# v1.40.0 — the Users module, round 2: cards, remembered devices, a filter, smooth limits, reports

By the version rule: new capabilities, so the second number goes up.

## What the owner asked

The third router is a TP-Link Archer C50 that reaches the second only over Wi-Fi, so its only mode is Range Extender
(Wireless Router and Access Point need a cable). The neighbours behind it should share one username and password
without fuss. From the list I proposed he picked seven items, plus «ui/ux ورود و اطلاعات رو هم به روز تر و بهبود
بده», with parallel agents.

## What is new

- **Remembered devices** (`user.remember`): a device that signs in on the router's page as such a user becomes theirs
  for good, as if the admin had picked it in the devices list (`devices[].remembered`, `at`). Picking another user
  for it clears the mark. Never for a card. The device limit still counts.
- **The repeater fix** (plan.addressOwners): behind a MAC-NAT repeater the neighbour table shows the repeater's MAC
  at every address, while the leases may name each phone's real MAC, which never appears on the wire. A lease's
  claim now holds only while its MAC answers somewhere (or nobody answers for the address). Otherwise the device
  answering for it owns it, so a user assigned to the repeater gets their routing, counters and speed.
  - A device that takes an ONLINE device's address still gets nothing.
  - A device that takes an AWAY device's address rides as itself, never as that device's user.
- **Cards (vouchers)** (`user.voucher`): made in batches on the new Vouchers tab, as ordinary user records
  (username = password = an 8-character code from an alphabet without look-alikes).
  - Each card has hours, GB, or both, and a device count.
  - The first sign-in (or the first bytes on a PC) starts it; a card's session ends with the card.
  - The cards print 8 per A4 page, with a QR of the sign-in page and the code filled in.
- **A content filter per user** (`user.filter`): blocked categories (adult → `category-porn`, social →
  `category-social-media-!cn`, games → `category-games`, ads → `category-ads-all`, each checked to exist in the
  geosite.dat the app downloads); a list of blocked domains; and safe search.
  - **How safe search works:** a freedom outbound per engine with `redirect` to Google's, Bing's, DuckDuckGo's and
    YouTube's safe host, dialled through the user's own config (over the chain relay through a ws hop). QUIC to
    those hosts is blocked.
  - **Where the rules go:** first among the user's rules, ahead of the router's own.
  - **What is left out:** a group config gets no safe search; without the geo files there are no categories (said
    in the log).
  - There is no "gambling" category: v2fly has no such list.
- **Smooth speed limits and a priority** on the router (router/shaper.js): HTB on the LAN bridge for the download
  and ingress + IFB for the upload, one class per device by its addresses, with fq_codel leaves.
  - **Priority:** high, normal or low under the line speed the admin enters.
  - **The router's own traffic:** goes in HTB's direct queue, so its pages and DNS are never starved.
  - **Without tc or the kernel pieces:** the v1.39 nft policing, and the Users page shows the
    `opkg install tc-tiny kmod-ifb` line. Nothing is installed by the app.
  - **Another shaper (SQM):** if one owns the interface, it is left alone.
- **Reports:** a 12-month history per user in their own calendar (`lanUsersMonths`) and a 12-month chart. There is
  also a CSV per user and for everyone (UTF-8 with BOM, so Excel reads Persian), and a printable monthly statement.
- **The sign-in and status pages, redesigned:**
  - **Sign-in:** username and password or a card code, as tabs that work without JS, with the username or the code
    filled in from the link.
  - **Status:** the limits as a ring and bars, the time left on the account or the card, the speed and why, the
    allowed hours, the admin's note and contact, and a top-up request the admin sees on the Users page.
- **Backup and restore of the Users module alone** (`lanusers:backup` / `lanusers:restore`): users, devices, cards
  and the meter's state, merged or replaced.

## Proven

- `npm test`: see the merge commit; new tests for the model, meter, IPC and hooks (lanUsersCore), sign-in by code,
  remember, requests and the shaper wiring (lanUsersRouterSignIn), the shaper's commands byte for byte
  (lanUsersShaper), the filter rules (lanUsersXray), the pages (lanUsersRouterPortal, the real-Chrome
  lanUsersPortalBrowser), the Vouchers tab and reports (lanUsersExtraUi), the Users page (lanUsersUi).
- **CI:**
  - **validate-configs:** 24 filtered shapes on the real cores.
  - **probe-lan-users** (cores job): a filtered user's blocked domain fails while another user's passes, and
    safe search redirects through their server.
  - **probe-lan-portal** (netns): remember, request, the spoof split (away / online), the repeater, cards.
  - **probe-lan-shape** (netns, new): a 2000 kbit cap within ±25 % and smoother than policing; high beats low.
  - **The QEMU guest:** the shaper falls back to policing without tc.

## Not proven

- On the owner's devices: the AC-1304 with tc-tiny + kmod-ifb installed, the Archer C50 as a repeater (which way
  its leases read), phones signing in with a card.
- Per-user DNS was not built: devices ask the router's own dnsmasq. The categories and safe search cover the
  "family" goal instead.
