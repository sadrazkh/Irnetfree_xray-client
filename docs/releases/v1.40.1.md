## The phone (Android)

- **A dead tunnel heals itself** (vpn/StallWatch.kt, `watchStall`).
  - **The problem:** a dead tunnel was noticed only when the phone changed networks. A server that died, a flow
    the ISP cut, or hev that stopped carrying sat at "Connected" until a manual reconnect.
  - **How it watches:** every 15 s it reads hev's own counters, one JNI call with no network and no radio wake.
  - **Traffic in, little back for two ticks:** the tunnel is asked through its own SOCKS port, twice, as the network
    watcher asks.
  - **Nothing back at all for three ticks:** that is hev, so the tunnel is rebuilt without asking.
  - **The rebuild:** the same seamless switch as the network watcher's, on the same budget (at most once a minute).
    A stall that rebuilding does not cure waits 1, 2, 4, 8 and then 10 minutes between tries.
  - **Idle or healthy:** nothing happens.
- **An unexpected error no longer ends the session or the app.** The session's checks (a coroutine scope with no
  handler) and the tunnel's worker commands now catch, log ("⚠ Internal error in …") and carry on. Before, any
  throw on those threads killed the process: the VPN dropped, a crash screen came up next time, and the sticky
  restart waited as if for a crash loop. startTunnel's whole body is inside its try now.
- **The in-process core's callback** answers an object's own methods and never lets an exception back into Go,
  which would be a native abort. Stopping the core is idempotent.
- **The log survives the app:**
  - every line carries the time of day and is written to a file by its own thread;
  - after a stop, the last lines of the run before open the Logs screen;
  - on Android 11+, why the system ended the app last time (memory, a native crash, ANR, a battery saver…) is in the
    log;
  - the Logs screen has Copy and Share, and it is shown in simple mode too.
- **Checked and found sound** (documented in the code): hev's start/stop order (stop joins; every start follows a
  teardown on the same worker), libv2ray's start/stop (a fresh controller each session; StopLoop is synchronous),
  the network watcher's timings, and no ANR paths.

## The cores

- **Suggested Xray is 26.10.31.** It is XTLS's emergency release: a listener on IPv4 MPTCP on Linux was reportedly an
  easy remote root, and 26.10.31 turns MPTCP off on listeners (#7291). That covers the router's LAN listeners and a
  phone sharing its connection.
- **Suggested Xray-PattN is 26.11.1** (upstream 26.10.31, plus the fork's `dialMode`, `merge` and `+one`, used from
  v1.41).
- The APK carries both (AndroidLibXrayLite v26.10.31, PattN v26.11.1).

## WireGuard

- **The bug:** "Destination name resolution" (`wgDomainStrategy`) wrote `settings.domainStrategy`, which Xray
  stopped reading in 26.9.30. On the suggested cores the choice was silently ignored.
- **The fix:** the built outbound now also carries `targetStrategy`, which Xray 26.10.31 reads (infra/conf/xray.go).
  An older core keeps reading the first and skips the second. Desktop and phone.

## Also
