# v1.38.0 — a config per app

By the version rule: a new capability (each program on a config of its own) — the second number.

## What the owner asked for

The first idea taken from ProxyDog (github.com/babaktaremi/proxydog): a config per app — Telegram on one server,
the browser on another, a program direct or blocked — «اره هر دوتاشو بساز منتشر کن». v1.37.0 shipped the other
(the live connections view).

## How

No injection: the desktop's sing-box TUN names each connection's program (`process_name`), so every listed app now
has a target instead of only "in or out of the tunnel".

- Settings `tunAppTargets: { [app]: '' (the connection) | 'direct' | 'block' | <serverId> | <groupId> |
  'chain:<id>' }` beside `tunAppMode` / `tunApps`; an app not in it does what its mode always did, so an existing
  store builds exactly as before.
- Xray: each distinct target gets a loopback SOCKS inbound `pa-<n>` routed to its outbounds — the users module's
  per-target machinery generalised (src/main/targetOutbounds.js; its output byte-identical), in buildConfig and
  buildPoolConfig, so groups, chains, multi-internet, WireGuard, ECH, the NIC binding and the chain relay reach them.
  A target that is gone blocks that app, said once.
- sing-box: one process_name rule per route after the port-53 rule (DNS still rides the tunnel), a socks outbound
  per `pa-<n>`, block as `reject` (the legacy outbound before 1.11). Ports from getFreePorts; the targets' entry
  addresses kept off the TUN. Shared connect / reload step for the desktop and the headless service.
- Refusals: not sing-box, native macOS, the router. Under the strict leak guard 'only' is refused whole and an
  excluded app sent direct is dropped by name; an app on a server of its own stays (encrypted, its own hole).
- The UI: a list — app, the Users page's config picker (configs by subscription, a gone one marked), ✕; several names
  at once, or from the connected apps. fa + en, RTL, 390 px.

## Proven

npm test (2881: tunAppTargets.test.js, tunAppLayout.test.js and the updated suites); validate-configs runs the
per-app shapes through `xray run -test` and `sing-box check`. A real TUN with per-app targets was not run here —
the owner's laptop is the first.
