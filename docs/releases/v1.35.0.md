# v1.35.0 — does a device on the Windows hotspot ride the tunnel?

By the version rule: a new capability (the hotspot check on the Users page) — the second number.

## What the owner asked for

«نمیشه یجوری باشه رو نسخه ویندوز هم هات اسپاتش همین کارو اتومات بکنه ؟ چون پروکسی اینا نمیشه اون قشنگ تره» —
the router's no-setup sign-in on the PC's Mobile Hotspot too. Then: «اره قدم ۱ رو بساز» — the test first.

## Why a test first

That mode would route each device by its source address inside the TUN (as the router does with sing-box
rule-sets), so it can only work if what the hotspot's devices send reaches sing-box's TUN with their own addresses
(192.168.137.x) — not sent around it by Windows' Internet Connection Sharing straight out of the Wi-Fi, and not
rewritten to the PC's own address first. Nothing here can say which; the owner's laptop can.

## The check

- **The devices on the hotspot**: the PC's neighbour table on the hotspot's address (`arp -a -N 192.168.137.1`,
  read-only; only the address lines are read — the headings are in Windows' language).
- **Whether the tunnel saw each**: on a Windows desktop with the users module, the TUN's sing-box gets its loopback
  API (`experimental.clash_api` on 127.0.0.1 with a random secret — tunSingbox `watch`);
  src/modules/lanUsers/hotspot.js reads `/connections` by source address and keeps what it saw (a connection lives
  seconds): when, how many open, the bytes. Field names read from a real sing-box 1.14.4 (a wrong secret is a 401);
  `sing-box check` of the config passes there and in CI (validate-configs `tun-windows-watch`).
- **A card on the Users page** (Windows): each device, «از VPN می‌رود ✓» / "Rides the VPN ✓" or not seen yet, and
  what the result means. Read on each page refresh; nothing runs in the background and nothing on the system is
  changed. No API (the router, a Mac, tun2socks, no users module): the config and the page as before.

## What the owner does

TUN mode on and connected, the Windows hotspot on, a phone on it with no proxy: open a few sites, refresh the
Users page. "Rides the VPN" → step 2 (sign-in page, a config per user on the hotspot) can be built; the phone has
internet but is not seen → the hotspot's traffic goes around the tunnel.

## Proven

npm test (2773: hotspot.js against fakes, the TUN config with and without the API, writeConfig only on a Windows
desktop, the payload, the card in both languages); CI `sing-box check` on the suggested sing-box.
