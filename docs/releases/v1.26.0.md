# v1.26.0 — WARP on WireGuard for a Chain, many accounts, the WARP+ account shown

## What the owner asked for

"WARP+ with license keys, as many as needed, in routing — not one WARP, several, especially in advanced routing";
then, more precisely: "plain WARP, not MASQUE — I have a config and want its exit to go through WARP, exactly like a
Chain". And: "when I make a WARP I give it a license, and it shows the license's details — accepted, has data or
not — all of it, and I can use it". Three things were agreed: the + WARP window gets a kind (WireGuard for a Chain,
or MASQUE); a Chain over a config of mine is made right there; several accounts in one go from a list of WARP+ keys,
their names numbered.

## What it does

- **«+ WARP» opens on WireGuard — for a Chain.** MASQUE is one click away and works as before.
  - **A new account**: the device key (X25519) is made on this computer and registered with Cloudflare — directly,
    or through the app's own connection.
  - **Several accounts**: a count (1–10) and a box of WARP+ keys, one per line. One key goes on every account;
    several go one per account in order, the accounts past them stay free; more keys than the count raise it. The
    box reads back as you type («۳ حساب: ۲ با WARP+، ۱ رایگان»), a malformed line by its number. A key is never
    shown again in full — only its last four characters.
  - **The Chain**: pick a server or a chain of yours; each WARP becomes the exit of a new chain «that config → ☁ WARP
    n». WARP's traffic then leaves from your server abroad, where WARP is not blocked: no clean IP, no noise. The
    last hop must carry UDP (an HTTP proxy cannot). «Select the chain» selects it, one press from connecting.
  - **Direct**: Cloudflare's WireGuard edge (162.159.192.1:2408, its IPv6, or a clean IP of yours) with anti-DPI
    noise.
  - **An account you have**: a WireGuard `.conf` (wgcf's, say) or a `wireguard://` link, chained or direct.
- **The account, shown**: after the key, the app reads the account back from Cloudflare — its type (free, WARP+
  with data, WARP+ Unlimited, team), whether the key was accepted (or Cloudflare's reason, e.g. too many devices),
  `premium_data`, `quota` and `usage` under Cloudflare's own names, the devices on it, and when it was read. One box
  per account when it is made; the same box in the server's editor; WARP / WARP+ on the server's card. MASQUE
  accounts made from now on get the same box.
- **A batch Cloudflare stops** (a 429 on the third sign-up, say) keeps what was made and says «2 of 5 accounts made —
  why».

## Underneath

- `src/main/warp.js`: `registerWarpWg` (POST /reg with our key, curve25519/wireguard; warp_enabled; the record's peer
  key, edges and `config.client_id` → Xray `reserved`), `accountStep` for both kinds (PUT …/account may answer 204;
  GET …/account and …/account/devices; failures are the warnings `licenseFailed` / `accountUnread`), `wgServerFields`
  (2408, MTU 1280, everything through it, noise only when direct), `accountLabels`, `licensePlan`, `resolveHop`,
  `importWg`; `addWarp` makes accounts one after another with a 2 s pause and returns `accounts`, `addedChains`,
  `stopped`. New error codes `badHop`, `badConf`. The WARP+ keys join the token and the private key in what is
  scrubbed from every log line and message.
- `server.warp` (AccountInfo) is kept on each server; the editor and the card read it. Nothing else depends on it.
- Desktop and router share the handler (`getChains` / `setChains` wired in main.js and service.js).
- Android: the same in `core/Warp.kt` and the WARP sheet (English). The X25519 key comes from the platform's
  `KeyPairGenerator("X25519")` — the bundled Conscrypt 2.7.0 on the phone, which IRApp installs first. A WireGuard
  `.conf` reader was ported from parser.js for the import (Android's general import still takes only links). An
  imported WireGuard used directly keeps its own endpoint on Android (the desktop applies the clean IP and noise).
- `scripts/probe-warp-chain.js` (CI, both suggested cores): the WireGuard server warp.js writes, behind a VLESS hop,
  against a sing-box WireGuard peer standing in for Cloudflare's edge — selected as the chain, then as an
  advanced-routing target; a page and 2 MB through it each time. Nothing reaches Cloudflare.
- `scripts/serve-renderer.js` listens on 127.0.0.1 only.
