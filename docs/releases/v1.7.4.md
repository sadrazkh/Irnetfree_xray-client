# v1.7.4 — the window loads again

v1.7.3 shipped with a syntax error in `src/renderer/i18n.js`: an apostrophe
inside a single-quoted English string (`WireGuard's`), added with the
managed-DNS hint of that release. The browser stops at the first script that
does not parse, so every script after it never ran and the window came up
dead — "nothing loads, everything is broken, stuck halfway" — on every
platform, on the release that was meant to be tested. The main process, the
core and the tunnel were fine; the UI could not reach them.

Nothing had checked that file: the main process never loads renderer code,
the renderer test reads it as text, and `npm test` was green. This release:

- fixes the string;
- adds `tests/syntax.test.js`, which compiles every JavaScript file under
  `src/main`, `src/renderer`, `src/server` and `scripts` (no execution) so a
  broken string, a stray brace or a half-finished edit fails the suite first.

Everything else is v1.7.3 unchanged: the WireGuard endpoint placed by the app
through a trusted resolver, the corporate resolver pinned to its domains, the
leak guard following the adapter, the managed-DNS warning.

`npm test` 782/782. `npm run validate` 183/183 on the official core,
195/195 on PattN + sing-box. The renderer files parse.
