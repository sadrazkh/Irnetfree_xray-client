# v1.31.0 — the ECH outbound (PattN's echOutbound)

By the version rule: a new capability — a server can fetch its ECH key through an outbound of its own — the second
number.

## What the owner asked for

A post by patterniha (2026-10-20, PattN P34 / PattNG P67): cloudflare-ech.com still opens over ECH, but the ECH key
can no longer be fetched over plain DNS. The way around it: `echConfigList` = `h2c://1.1.1.1/dns-query` and an
`echOutbound` — a `direct` outbound that redirects to 1.1.1.1:443 under TLS as `www.microsoft.com`, the certificate
checked with `verifyPeerCertByName: "fromMitM,www.microsoft.com"`, `alpn: ["fromMitM"]`. «ببین چیه لازمه و من ندارمش
تو کلاینت اگر اضافش کن و تگ بزن بره بالا».

## What it is

- `echSockopt` is the official core's own; `echOutbound` is the PattN/PattNG CLIENTS' (PattN's V2rayOutboundService:
  the outbound is appended to the config and `tlsSettings.echSockopt.dialerProxy` names it). Share links carry it as
  `echOutbound=<one-line JSON>`.
- The official core does the rest since 26.10.10: an `h2c://` query is sent as HTTP/2 without TLS through the dialer,
  with the query's host handed to that outbound (`fromMitM` → 1.1.1.1, verified against the resolver's certificate).
  26.9.30 and older say "http2: unsupported scheme" (seen here on 26.3.27) or cannot verify.

## What it does

- **Links** (vless/vmess/trojan/ss/hysteria2): `echOutbound` read — comments and trailing commas too, as PattN writes
  it — and kept on the record inside tlsSettings; written back into share links with a tag (PattN refuses one without).
- **The config** (desktop, router, Android; connect, pool, pings): taken out, given our own tag `ech-<n>` (identical
  ones share one), appended, and `echSockopt.dialerProxy` points at it. Under TUN it is bound to the NIC like any
  direct dial and its redirect address is the strict guard's hole. Without a DNS-fetched list it means nothing and is
  dropped. The live meter leaves `ech-*` out.
- **The editor** (Pro view, Security → ECH): an "ECH outbound" JSON field with an **Example** button that writes the
  pair — the post's outbound, and ECH as `<name>+h2c://1.1.1.1/dns-query` (the field's own name kept;
  cloudflare-ech.com when empty). Desktop and Android.
- **The core version**: an ECH outbound needs Xray 26.10.10+. An older core runs it on the other Xray core when that
  one is new enough; otherwise the connect says to update under Settings → Required files. The bundled Android cores
  (libv2ray 26.10.10, PattN 26.10.13) already are.
- sing-box does not use it.

## Proven

- CI (`scripts/probe-ech-outbound.js`, real network, both suggested cores 26.10.10 and PattN 26.10.13): with the
  Example outbound, cloudflare-ech.com/cdn-cgi/trace says `sni=encrypted`; the same h2c query without it gets no key
  (the connection is refused). The cores' `-test` accepts the link form plain, under TUN and under the strict guard.
- This machine (Iran, 2026-10-20, Xray 26.3.27 — too old for h2c): plain UDP DNS answers but brings no usable key and
  every connection to cloudflare-ech.com is reset — what the post describes.
- Desktop tests: tests/echOutbound.test.js, the gate in tests/xrayManager.test.js. Android: EchOutboundTest.
