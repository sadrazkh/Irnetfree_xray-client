# v1.45.3 — A warning when the way out stops answering

By the version rule: an improvement to something that already exists, so the third number goes up.

## What the owner asked

After v1.45.2 showed that a dead default route, not advanced routing, was behind "as if nothing happens", he asked for the warning: «آره هشدارو بساز».

## Why it was needed

"Connected" says the core runs, not that anything passes. Under advanced routing, names are resolved through the default route. With a dead default no name is found, not even for a site with a rule of its own, and changing a rule's target changes nothing. Nothing on screen said so.

## What changed (desktop, router)

While connected, a small request goes through the app's local SOCKS port: 8 seconds after a connect, then every 2 minutes (3 on a router). Two misses in a row and a line appears under the connection state, with a toast once, until it answers again. A window opened later learns it too.

| Plan | What it says |
|---|---|
| Advanced, managed DNS | The default "X" does not answer. Names go through it too, so no site can be found, not even one with a rule. Change the default. |
| Advanced, managed DNS off | The default "X" does not answer, so sites with no rule will not open. Change the default. |
| One server or a chain | "X" is connected but does not answer. Try another config. |

Nothing is said for what would never answer the test: a default of direct or block, a split-tunnel WireGuard, a pool, or a raw JSON server. It starts no core and changes no route, and nothing is asked during a connect, a recovery or a reload.

## Limits

- **Only the default is measured**, not each rule's target. A dead target of a rule is not reported.
- **A rule that names the test site** (`cp.cloudflare.com`) would make it measure that rule's target instead, so at worst it says nothing.
- **Android** does not have it yet.

## Tested

- `npm test`: tests/routeWatch.test.js (what is said for which plan, one miss said nothing, two in a row once, an answer takes it back, nothing asked while busy, a late answer after a disconnect ignored, the router's service end to end, the snapshot for a window opened later).
- Real servers, behind his router as it was, with the app's own probe on a throwaway core: the Reality and pinned ones warned and the `ws` ones did not.
- The real page in headless Chrome, in both languages: the line appears, leaves when it answers again, is ignored after a disconnect, and comes back from the snapshot.

## Owed

Nothing here ran in the real desktop shell or on the router.
