# v1.18.0 — ECH, the newer link parameters, Hysteria2, and configs written for the core that runs them

Asked for by the owner: the settings recent v2rayN and Xray(-PattN) links carry and this app did not read — ECH first
(`ech=cloudflare-ech.com+udp://1.1.1.1`) — handled completely, on every platform at once. First published as the
pre-release **v1.18.0-beta.1** for testing; nothing here reaches anyone through the in-app update until the final tag.

## Every platform (Windows, macOS, Linux, the router, Android)

- **ECH (Encrypted Client Hello)** — `ech=` is read into the core's `echConfigList`: a base64 config, or where to fetch
  it from DNS (`name+udp://1.1.1.1`, `name+https://…/dns-query`, kept exactly — the `+` is part of it). Under TUN the
  core's own lookup is bound to the physical adapter like every direct dial (it would otherwise enter the tunnel that is
  waiting for its answer); a resolver given by name is resolved before the connect; under the strict leak guard a UDP
  query to 1.1.1.1 / 8.8.8.8 / 9.9.9.9 is made over DoH on the same address and gets its firewall hole. On sing-box
  the same link becomes sing-box's own ECH.
- **Certificates** — `pcs` (the certificate's SHA-256 — the core's replacement for allowInsecure, a self-signed
  certificate too) and `vcn` (verify the certificate against this name instead of the SNI). A link that names its
  certificate is no longer pinned on first use; a pin it brings and one learnt on first use are sent together.
  sing-box has no setting for either, so a server with `pcs` / `vcn` that runs on sing-box skips the certificate check
  there, as allowInsecure did — on Xray both are checked.
- **REALITY** — `pqv`, the server's ML-DSA-65 key (post-quantum check). A malformed key is dropped (and refused in the
  edit form) instead of making the core refuse the whole config.
- **Transports** — gRPC `authority`, mKCP `mtu`; `insecure` / `allow_insecure` read like allowInsecure; VMess links
  read the second values where v2rayN writes them (gRPC host → authority, type → mode; kcp path → seed).
- **mKCP works again** — every 2026 core refuses mKCP's `header`/`seed` ("removed and migrated to finalmask"), so
  every kcp server failed to start. The app now asks the core it is about to run for its version and writes the masks
  in the form that version takes (header-* / mkcp-original / mkcp-aes128gcm, or mkcp-legacy from 26.6.1).
- **Hysteria2** — `hysteria2://` and `hy2://` import and run natively on both Xray cores (auth, SNI, pinSHA256, ECH,
  salamander obfs, port hopping written for the running core's version, up/down). One that asks for `insecure=1`
  without a pin runs on sing-box: the Xray cores have no way left to skip the check, and pinning on first use cannot
  work over QUIC. Its TCP ping shows "—" (UDP only); the real delay is measured — on sing-box where it runs there.
- **Shadowsocks plugins** — `obfs-local` (obfs=http) and `v2ray-plugin` (websocket, with or without tls) become the
  matching transport (sing-box runs them as plugins); any other plugin is refused by name instead of imported without
  it.
- **Edit form** — ECH, pcs, vcn, pqv, gRPC's authority (the Host field) and Hysteria2's fields; share links / QR carry
  everything back, and a subscription refresh keeps what you edited.
- **sing-box** — besides ECH and Hysteria2: httpupgrade, WebSocket early data (`?ed=`), the TLS fragment.

## Android

- The same parser, config forms and edit sheet. httpupgrade links now keep their path and Host (they were lost).
- A Hysteria2 with insecure and no pin runs — and is tested — on the bundled sing-box (arm64).
- Known limit: ⚡ (fastest) ranks by a TCP handshake first, so UDP-only servers (Hysteria2, WireGuard) are not picked
  by it; use Test on the server.

## Check on your own devices

- Paste the ECH link from the request and connect in TUN mode (standard leak guard) on Windows, then on the router and
  Android; the log must not show "Failed to query ECH DNS record".
- Edit a server: type an ECH value, save, copy the link — it carries `ech=`.
- A kcp server (if you have one) connects on Xray 26.3.27 and on 26.9.x.
- A Hysteria2 link with and without `insecure=1`: the first on sing-box, the second on Xray.
