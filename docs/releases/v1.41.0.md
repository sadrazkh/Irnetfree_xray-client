# v1.41.0 — PattNG's presets in the editor, Xray-PattN's dialMode, hellochrome_120

By the version rule: new capabilities, so the second number goes up.

## What the owner asked

After the PattN / PattNG / v2rayNG survey of v1.40.1, the editor additions he approved, as one list: PattNG's
presets for finalmask and cipherSuites, the fork's `dialMode` as a field of its own, the `hellochrome_120`
fingerprint, and every server that needs the fork run on it. The suggested Xray-PattN 26.11.1 (v1.40.1) already
carries `dialMode` and `merge`.

## What is new

- **Presets beside a field** (serverFields.js `presets`, one table for the window, the router's page and the phone).
  - **What it is:** a small «آماده» / "Presets…" picker beside a free field.
  - **A pick:** fills the field, which stays editable.
  - **What the picker shows:** the preset the value equals now, or its placeholder for a value of one's own. JSON is
    compared by its canonical form (the same mask pretty-printed or in another key order is the same mask),
    cipherSuites by its names in order, any other field by its text.
  - **Where:** the Pro view of every editor, and the Simple view's cipherSuites and finalmask on the desktop, the
    router and the phone.
- **PattNG's presets, name for name and value for value:**
  - **finalmask:** `tlshello-0-len (0-104-1-0-0-114-1-1-11)` and `tlshello (6-98-1-0-0-114-1-1-11)` (two
    ClientHello splits each), `udp-noise (rnd-24-1200-1230)` (24 noise packets before a UDP handshake) and `merge`
    (the fork's TCP mask: `times` 100, `delayMs` 30, `maxBytes` 16384);
  - **cipherSuites:** `semi-python-cipherSuites` (10 suites) and `real-firefox-cipherSuites` (12), the names joined
    by `:`;
  - **dialMode:** `oob` → `oob.0`.
- **dialMode, a new field** (Advanced → 🧩 patterniha, the anti-DPI extension's, this device only):
  `streamSettings.sockopt.dialMode` for VLESS, VMess, Trojan and Shadowsocks.
  - **What it does:** `oob.<byte>[,<byte>…]` sends each byte (0–255) as urgent (out-of-band) data with one of the
    first TCP writes. `oob.0` sends one 0x00 with the first; `oob.0,32,65` sends a byte with each of the first three.
    UDP is left alone.
  - **What the editor refuses:** anything else, in words, in both languages ("oob. and then bytes 0–255, separated
    by commas"). The core takes nothing else: every dial fails with "unsupported dialMode".
  - **Counted:** a server with one is counted as using the anti-DPI extension.
- **hellochrome_120** in the fingerprint lists, right after chrome.
  - **Where it runs:** it is one of the official core's own fingerprints, so it runs on both Xray cores.
  - **Where it is left out:** AnyTLS's list, since sing-box's uTLS has no such name.
  - **Links:** a link carrying `fp=hellochrome_120` keeps it on the desktop, the router and the phone.

## A server that needs the fork runs on it

- **What counts:** any outbound with a non-empty `sockopt.dialMode`, or a finalmask with a `merge` item
  (xrayManager.pattnOobNeeds).
- **Desktop and router** (xrayManager.validateWithFallback, the same for main.js and service.js): such a config
  runs on Xray-PattN whatever core was asked. The official core is never asked: it has no `dialMode` and would
  dial without it.
- **PattN older than 26.10.27:** the connect is refused in plain words: "Xray-PattN 26.10.22 does not know dialMode
  oob (26.10.27 and newer do) — update it under Settings → Required files". It is never -tested, because an older
  PattN passes the config and then fails every dial.
- **No PattN installed:** refused with the install message, and the window offers the download as it does for a
  finalmask.
- **The phone** (EngineChoice.chooseEngine): a server that names no core of its own and carries either one runs on
  the bundled PattN 26.11.1, alone or anywhere in a plan (a chain, a group's member, the pool, a routing profile).
  - **Rules that come first:** groups, MASQUE and TUIC / AnyTLS keep their own.
  - **Latency tests:** they follow the same core.

## Proven

- **npm test** (Windows): 3043 pass, 10 skipped. 7 fail: the LuCI plugin's and fw-forwardings.sh's shell tests,
  which fail the same way on the untouched v1.40.1 commit on this machine. New tests:
  - the presets (PattNG's values exactly, presetOf's matching), the field and its check, and the fingerprint
    (serverFields);
  - the editor's refusal and the Simple view's markup and wiring (serverEditorUi);
  - the Pro view's pickers: a pick, typing, the placeholder (masqueUi);
  - a link with hellochrome_120, and dialMode written, kept and cleared, never in a share link (parser);
  - the routing and its three refusals (xrayManager);
  - the extension's count (modules);
  - the core gate's new shapes (validateConfigs).
- **The core gate** (validate-configs, the `cores` job):
  - **On both cores:** dialMode in every editor config, and beside the anti-DPI dialer, the NIC binding, the pinned
    names and a chain's hops.
  - **On Xray-PattN alone** (`IRNF_XRAY_FORK=pattn`, as its banner reads "Xray <version>" too): the merge mask
    (with dialMode too) and PattNG's two ClientHello splits.
- **Checked here on real cores:**
  - **dialMode:** the official 26.10.21 loads every dialMode shape and editor config, ignoring the key.
  - **merge:** the official 26.10.21 and Xray-PattN 26.10.22 both refuse it ("unknown config id: merge"), which is
    why a version older than 26.10.27 is refused before any -test.
- **Android:** JVM tests for EngineChoice (needsPattn, the plan rules), the generated table's presets, dialMode's
  check and its write into sockopt, and the extension's count. The Kotlin compiles in CI only.

## Not proven

- **On the owner's devices:** a dialMode server through a real ISP, and the merge mask on the real Xray-PattN
  26.11.1 (the cores job runs only `-test`).
- **Not done here:**
  - **dialMode with a fragment or noise, or on a chain's later hop:** the OOB bytes go only where an outbound dials
    its own socket, and an outbound that dials through the anti-DPI dialer (`dpi-*`) or through another hop does
    not. The app does not move dialMode onto that dialer.
  - **finalmask's presets on a MASQUE server:** they are offered there too. Its finalmask is the official core's own,
    which never knows `merge`.
  - **hellochrome_120 on a server set to sing-box:** sing-box's uTLS would refuse it, as it refuses `unsafe`.
