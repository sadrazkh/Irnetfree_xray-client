# v1.36.0 — TUIC and AnyTLS, on the sing-box core

By the version rule: a new capability (two protocols) — the second number.

## What the owner asked for

After v1.35.2 named what the app could not import («چیا دیگه اینشکلین؟»): `tuic://` and `anytls://` were refused
as unsupported. «شروع کن بزن بره همهرو».

## How

sing-box has both protocols; neither Xray core has either. So a TUIC / AnyTLS server runs on sing-box, on its own,
or not at all — desktop, headless service and Android (bundled sing-box 1.13.14; AnyTLS needs 1.12+).

- **Links**: `tuic://uuid:password@host:port` (sni, alpn, congestion_control, udp_relay_mode, allow_insecure /
  insecure, reduce_rtt / zero_rtt_handshake, heartbeat, disable_sni) and `anytls://password@host:port` (sni, fp, alpn,
  insecure) — read and written back; a sing-box JSON with them imports. The record keeps an Xray-shaped outbound
  (`settings.servers[0]`, `tlsSettings`) like every other kind; Xray never runs it.
- **sing-box**: TUIC over QUIC, ALPN h3 by default, no uTLS; AnyTLS over TCP with uTLS and the fragment.
- **Where they cannot run, said by name** (fa and en): sing-box not installed; inside a chain, a group, a routing
  rule or the pool (only an Xray config holds those); on the router (it runs every config on Xray); pinned (`pcs`,
  `vcn` or a pin learnt on first use — sing-box keeps no pin, and there is no Xray to fall back to; v1.35.1's rule).
- **No trust-on-first-use pin for them**: their `allowInsecure` is sing-box's `insecure` on purpose (as a
  Hysteria2's with no pin) — a pin learnt there would leave them nothing to run on.
- **The editor**: both protocols, TUIC's congestion control, UDP relay mode, 0-RTT, heartbeat and disable-SNI,
  AnyTLS's fingerprint; the engine fixed to sing-box. Android's field table regenerated from serverFields.js.

## Proven

npm test (2804, tests/tuicAnytls.test.js among them); `sing-box check` of every TUIC / AnyTLS config the app builds
(validate-configs); scripts/probe-tuic-anytls.js in CI's cores job — sing-box's own TUIC and AnyTLS servers on
127.0.0.1 with a generated certificate, the app's client config from a parsed link: a page, 1 MB whole, UDP
through each (TUIC native and quic), a wrong password gets nothing. Android: TuicAnytlsTest.kt in CI.

## Not yet

No real TUIC / AnyTLS server on the internet tried; Android on a device; a pinned TUIC / AnyTLS stays refused
until the owner decides.
