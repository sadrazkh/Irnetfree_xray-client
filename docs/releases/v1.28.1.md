# v1.28.1 — A group drops a dead member within seconds; every config picker by subscription; a WireGuard's lost hop named

A pre-release. The first number by the version rule the owner asked for: the third digit for fixes and for making
what exists better, the second for a new capability, the first for a break.

## What the owner asked for

"If there are several paths and some of them break, set them aside, test them now and then to bring them back, and
use only the ones that work"; "the config list split by subscription — I want it everywhere: routing, advanced
routing, chain, every part of advanced routing, wherever a config is chosen, so it is clear where it comes from";
"I made a plain WARP, put it in advanced routing, last step through one of the configs — the core gave an error".

## What it does

- **A group sets a dead member aside within seconds** — the core's health check now asks every 10 s (was 30 s); a
  member that stops answering is out of the rotation fast and back as fast. The log says when one leaves, when it
  comes back, and when none answers (its traffic then waits on the first). Desktop and router.
- **Every config picker by subscription** — a rule's target and its via, the default and its via, the base, the
  pool, the Home picker, WARP's first hop and a group's «+ IP تمیز» select: hand-added, each subscription, chains,
  groups, each under its own head. In the search-select the piles fold (remembered; the one holding the pick is always
  open), a search matches a pile's name too, and the closed select says the pick's subscription («UK 2 SNI · Irancell
  UK»). The native selects use `<optgroup>`.
- **A WireGuard's lost hop, named** — when the config a WireGuard (a WARP above all) goes through stops carrying it,
  the core says only `proxy/wireguard: unexpected closed > io: read/write on closed pipe`. The log now adds, once a
  connection, which WireGuard lost which config and that it is that config which is not working. Desktop and router.

## The WARP report

Reproduced on the owner's own «Routing 2» (base: the group «Irancell UK SNI») built the way the app builds it, on his
own cores: the config check passes on the engine the plan picks (PattN 26.9.1) in every shape — WARP as a rule target
through a config, through the base group, the chain [config → WARP] as a target or the default, WARP direct with its
noise. Run for real: through a working config the WARP's traffic leaves with no error; through «IRbaUK2🇬🇧-Sadra» —
whose own REALITY fails with "received real certificate" — every request prints the line above. The builder was
right; the hop was down, and nothing said so.

## Underneath

- `configBuilder.GROUP_PROBE.interval` 10 s; `stats.GroupHealthWatch` (changes only, reset at connect).
- Renderer: `configOptions()` (value, label, pile), `pileFolds`/`setPileFold` (`irnf.pileFold`), `pileHead`;
  `makeSearchSelect` piles; `renderPicker` piles when more than one; `targetOptions` optgroups; `targetOptionList`
  now lists direct and block first.
- `stats.wgRides(plan)` (a rule's via, the base for inherit, a chain's member before) and `stats.WgHopWatch`.
