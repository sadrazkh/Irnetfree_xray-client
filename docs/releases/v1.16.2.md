# v1.16.2 — The router ran out of open files

On the owner's AC-1304 (OpenWrt 23.05.4, v1.16.1) the whole house lost the internet a minute after every connect: the
laptop, the phone and the PC could not browse, then it worked again, then it broke again. The router's log showed
two things. First, the core's DNS over HTTPS through the server timed out again and again ("app/dns: failed to retrieve
response for google.com … context deadline exceeded", for 1.1.1.1 and 1.0.0.1). Then, 49 to 90 seconds after "TUN mode
active", sing-box printed hundreds of lines ending in "socket: too many open files". This release fixes both, on the
router only. The Windows, macOS, Linux and Android apps build exactly the configs they built in v1.16.1.

## What happened

- Every UDP flow from the LAN (each DNS query dnsmasq forwards, each game or call) becomes a SOCKS association inside
  the router: two open files in sing-box and a listener in the core, kept until the session expires, which by default
  is **5 minutes**.
- When the server's DoH timed out, the core sent the LAN **no answer at all**. Every device retried, and dnsmasq resends
  a retry from the same port. On the sing-box versions OpenWrt ships (1.11 on 23.05, 1.12 on 24.10), that second packet
  stretched each DNS session from 10 seconds to the full 5 minutes.
- The service, and the cores it starts, could open at most **4096 files**: OpenWrt's procd sets no limit, so they had
  the kernel's default. Retried DNS, QUIC and ordinary connections (six open files each in sing-box) used that up in
  about a minute. After that sing-box could not open a single new connection, so no device could browse until old
  sessions ran out.
- The router's in-country DNS was set to 1.1.1.1 and 8.8.8.8, very likely from a desktop backup restored before v1.16.1.
  That did not cause the timeouts, but it sends Iranian names in plain text to public resolvers from inside Iran.

## What changed (router only)

- **65536 open files.** The service's init script now gives node, sing-box and Xray 65536 open files (procd `limits`,
  the same setting OpenWrt's own xray-core package uses with a much larger number). A storm that used to fill the
  budget in a minute now leaves it mostly free.
- **UDP sessions last 2 minutes, not 5.** The router's TUN now sets `udp_timeout` to 120 seconds, so retried DNS
  queries and other idle UDP flows let go of their files much sooner. 120 seconds is the shortest a NAT should keep a
  UDP mapping (RFC 4787). On the router's sing-box the same timer also ends a TCP connection that has been silent in
  both directions for 2 to 4 minutes; apps whose keepalives are more often than that are not affected.
- **DNS over HTTPS with room to connect.** The router's core now gives each DoH server 8 seconds instead of 4, asks
  both DoH servers at once instead of one after the other, and keeps answering names it already knew (from cache, for
  up to a day) while the server's DoH is down, refreshing them in the background. For Iranian names the in-country
  resolvers' answer is still the one used, though the DoH servers are asked at the same time. With any other resolver
  in the list (a plain one, or a corporate WireGuard's — with or without search domains) the queries stay one after the
  other as before, so a company's names never reach the public DoH servers.
- **The router says its budget.** At every connect the log says how many files node, Xray and sing-box have open and
  how many they may open; it warns, in the system log too, when a core got less than it should. LuCI's "Copy
  diagnostics" carries the same line, and a "too many open files" from a core becomes one clear error line a minute
  with the numbers.
- **A one-time repair of settings a desktop backup overwrote.** The first start of v1.16.2 checks the router's stored
  settings once. If they clearly came from a desktop backup (an in-country DNS of public resolvers only, or a desktop-only
  switch), it turns the QUIC refusal and "Connect when the router starts" back on and puts the in-country DNS back to
  the default Iranian pair. It says exactly what it changed in the log; each value can be set back under Settings, and
  it never runs again. The kill switch, routing mode, DoH list and rules are left alone.

## Not changed

- The desktop apps (Windows, macOS, Linux), the headless server off a router and Android: their sing-box and Xray
  configs are byte for byte those of v1.16.1, and tests pin that.
- Routing on the router is unchanged. A routing change that would avoid DNS lookups for sniffed connections was
  considered and left out: it changes which traffic goes direct for apps that connect by name.

## Good to know

- **Restart is enough.** Installing the package restarts the service with the new limit. To check it on the router:
  `grep 'open files' /proc/$(pidof sing-box | cut -d' ' -f1)/limits` should say 65536, and the log's "Open files at
  connect" line shows the same for all three.
- **Check the one-time repair.** `logread -e irnetfree | grep 'repaired once'` shows what it changed, if anything.
- **If browsing still stalls**, send LuCI → Services → IRNetFree → Log → Copy diagnostics. The open-files line and
  the order of the DoH errors in the log show whether the server's DoH, the budget or something else is at fault.
