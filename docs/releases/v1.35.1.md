# v1.35.1 — a pinned certificate is never "accept any" on sing-box

By the version rule: a fix to something that already exists (certificate pins on a server set to sing-box) — the
third number.

## The hole

`translateTls` (src/main/singboxBuilder.js; Android's SingboxConfig.kt the same) wrote `tls.insecure = true` for a
record with `pcs` (pinnedPeerCertSha256) or `vcn` (verifyPeerCertByName), and a link that asked for allowInsecure
kept it even after the app had pinned its certificate on first use (server.certPin). On sing-box such a server
accepted ANY certificate: a man in the middle unnoticed. sing-box can keep none of the three — it pins a public key
(`certificate_public_key_sha256`), not a certificate, and has nothing like `vcn`.

When it could happen: a single server the user set to the sing-box core (engineChoice: groups, chains and the
default engine never run there; the router never runs sing-box).

## The fix

A TLS record with `pcs`, `vcn` or a pin learnt on first use is not sing-box's: the translator throws, and the
fallback that already existed runs it on Xray, which keeps all three — the connect log says why ("sing-box: this
server's certificate is pinned … — using Xray"; Android: "— using the in-process core"). A ping measures it on Xray
too. Every protocol the translator handles runs on Xray, so nothing pinned has to stay on sing-box, and no probe of
the certificate's public key is needed.

Unchanged on purpose: a Hysteria2 with allowInsecure and no pin keeps sing-box's insecure (needsInsecureCore — the
Xray cores can no longer skip the check, and pinning on first use cannot work over QUIC); REALITY has no
certificate. The TUN's sing-box never carries a server's TLS: its outbounds hand traffic to Xray on 127.0.0.1 or go
direct.

## Still the owner's call

A pinned record Xray cannot run (only an installed Xray too old for its protocol, with no newer core) now fails to
connect with Xray's own error — never insecure. Running it on sing-box unverified with a warning instead is the
alternative; it was put to the owner.

## Proven

npm test (2775): pcs, vcn, a pin on first use (TCP and Hysteria2) refused on sing-box; no pin → as before; REALITY
untouched; the four callers' fallbacks; every TUN outbound shape carries no TLS. `sing-box check` (1.14.4) of the
configs that still run on sing-box.
