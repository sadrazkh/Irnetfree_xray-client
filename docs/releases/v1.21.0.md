# v1.21.0 — The base sits between you and the target; exit at the base; the direct share on screen

## What the owner asked for

Looking at v1.20.0's flow tree:
- "the base is between me and the target, not after the target";
- show the simple routing mode too ("I set Iran direct, that should be visible"), both on the routing page and on the
  home screen, so it is clear how much traffic went direct;
- "I may pick a base and want the traffic to leave from it — the default should be my base itself".

## The flow tree (desktop, the router's web UI)

- **Columns in the order traffic takes them**: rules → bases → targets. A rule through a base points at the base, and
  the base points on at the target. A rule without a base points straight at its target.
- **The app's own rules are drawn where the core matches them**, read-only and marked as the app's:
  - 🚫 Ads → Block, before the user's rules, while ad blocking is on;
  - 🏠 Local network → Direct, after them (always);
  - 🇮🇷 Iran / 🇨🇳 China → Direct, after them, when the profile applies the simple routing mode (bypass Iran / bypass
    China);
  - then "everything else".
- Clicking an app rule opens what it comes from: the ads switch, or the routing mode.

## Exit at the base

- **A new target, "⚓ Exit at the base"**, for any rule and for the default, offered while the profile has a base.
  Traffic goes to the base and leaves to the internet from there.
- **It follows the base.** Change the profile's base and every "exit at the base" goes with it.
- **At connect it is the base itself, dialled directly** (its own outbound, no via). The rest of the config is
  unchanged.
- **Without a base it is marked** on the routing page:
  - a rule at the base is left out;
  - a default at the base refuses the connect with the reason.
- **Share links carry it as it is.** An older version refuses such a link with its usual "names something it does not
  carry".
- **In the tree**: rule → ⚓ base → 🌐 out to the internet, counted on the base's own outbound.

## The home screen

- **A profile's lines put the base between the condition and the target**: `condition → ⚓ base → target`. A line at the
  base reads `condition → ⚓ base`.
- **The simple mode's country gets its own line** with its direct traffic:
  - on a profile that applies the mode;
  - under a single server or a chain in bypass Iran / bypass China (or everything, in direct mode), as a line under the
    path.

## Android

- The same "⚓ Exit at the base" target in the rule and default pickers, resolved the same way at connect. A default
  there without a base refuses with the reason.
- The flow list reads rule → ⚓ base → target (or 🌐 leaves here), among the app's own rules in the config's order:
  ads, local network, the routing mode's Iran/China bypass.
- Android has no per-outbound counters, so no traffic figures there, as before.

## Unchanged

Every config without an "exit at the base" target is byte-identical to v1.20.0: the builders did not change. The
target is resolved before the plan reaches them.
