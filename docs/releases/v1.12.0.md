# v1.12.0 — Android: connect to the fastest

Android only. Nothing in `src/` changed (`npm test` 796/796) — this is the
Windows picker's ⚡ row, on the phone.

## What it does

**⚡ connect to the fastest**, on the Connect screen under the exit chip, and as
the first row of the exit picker (which is where Windows keeps it). It appears
once there are two servers to choose between, exactly as on the desktop.

One tap: it measures, picks, **saves the choice**, and connects.

## It says which one it picked

Three ways, because an auto-connect you cannot audit is a mystery, not a
convenience:

- the choice is **saved as the selection**, so the exit chip and the connected
  line name it like any other server;
- a line under the chip says what it chose, out of how many, and on what
  measurement — `⚡ fastest of 13: 🇩🇪-CDN1 · 340 ms through it`;
- the same sentence goes to **More → Logs**, where it is still there tomorrow.

## How it measures

Windows measures a real round trip through every server at once. A phone cannot:
each one costs a throwaway core. So it is two stages.

1. **The handshake to all of them**, eight at a time, 3s timeout. A TCP connect
   is a socket and nothing else — thirteen servers cost about three seconds, and
   a server whose port is shut is out of the running for free.
2. **A real HTTP round trip through the three that answered quickest**, each on
   a throwaway xray (`XrayTester`), 5s timeout. This is the measurement that
   separates a server that carries traffic from one that merely accepts
   connections.

Both numbers go to `Fastest.pick`, which is the desktop's own arithmetic
(`bestServerId` in `renderer/app.js`): **a server that really carried a request
beats one that only shook hands, however fast the handshake was.** A dead exit
still completes a handshake in 40ms, and that is precisely the server this
feature must not hand anybody. Handshake-only servers are scored in a band above
every measured one (`100000 + ms`), so they win only when nothing carried
anything at all — which is still a better answer than none.

The progress is on the pill itself (`testing 8/13…`, `checking 2/3 · …`), the
pill is dead while it runs, and the throwaway core is stopped even if you leave
the screen mid-test (`NonCancellable`).

## What it does not do

- **Nothing answered → nothing changes.** The selection you had is the selection
  you have, with a line saying so.
- **Chains, the pool and advanced routing are not candidates**, the same as on
  the desktop: this ranks servers.
- **It never asks for VPN permission behind your back.** If consent has not been
  given yet, the system dialog is shown for this tap like any other connect.
- Already connected: it disconnects first and reconnects on the new choice, the
  way the reconnect button does.

`FastestTest` (8 tests) pins the ranking rule: the handshake-only band, servers
that never answered not being candidates, ties keeping the earlier server, the
shortlist being the quickest few and never the dead ones, and the mixed list the
UI actually produces.
