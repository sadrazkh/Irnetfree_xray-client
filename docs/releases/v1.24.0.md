# v1.24.0 — The full server editor

## What the owner asked for

VLESS Encryption (the "Encryption" value 3x-ui and the other panels now show) worked through links, but nothing in
the app could show or change it, and many other fields had no input either. The ask: every field a server can have —
"whatever all the clients have, the most complete" — as a simple view like today's, with a professional editor one
click away in the same window, and the patterniha parameters where they are. A sample was approved first.

## What it does

- **One window, two views.** A `Simple | Pro` switch in the edit window's head; it opens in the view used last.
  Both edit one draft, so switching never loses a value.
- **Simple** is today's form with what it lacked:
  - VLESS flow and VLESS Encryption;
  - the VMess cipher and Alter ID;
  - the Shadowsocks method, as a list.

  The anti-DPI and 🧩 patterniha sections are as they were.
- **Pro** has five tabs: Basics, Protocol, Transport, Security, Advanced. Each shows only the fields of the chosen
  protocol, transport and security, and under each tab's name is what is chosen there.
  - **Protocol:** every protocol's fields, from VLESS Encryption to a WireGuard's keepalive and a Shadowsocks
    plugin.
  - **Transport:** RAW with its HTTP header; WebSocket's heartbeat; gRPC's mode, authority and timeouts; XHTTP's
    mode, extra, XMUX and a split download; every mKCP knob.
  - **Security:** TLS with ALPN, certificate pin, ECH and its force mode, TLS versions and curves; REALITY with
    spiderX and the ML-DSA-65 key.
  - **Advanced:** Mux for this one server (the app's setting, on or off, and its own numbers); socket options
    (TCP Fast Open, MPTCP, keepalive, congestion); anti-DPI; patterniha.
- **VLESS Encryption, read back.** Paste the panel's value, and the window says what it is:
  - the auth: X25519, or ML-KEM-768 (post-quantum), told by the key's length;
  - its mode and 0-RTT or 1-RTT;
  - or why it is not a valid value.
- **A server from scratch.** A new add button: "+ Manual" on the desktop and in the router's web UI, Add → Manual
  on Android. Pick the protocol, fill the tabs; the server gets its own share link.
- **"This device only"** marks every field a share link cannot carry. Those stay in the app's store and backups.
- **A save that cannot go through says why:** it names the field, marks its tab with a dot and opens it. Numbers,
  ranges like `16-32`, JSON and the Encryption are all checked.
- **Persian and English** for every label, hint and message. Android shows English, as the rest of its UI does.

## What changed underneath

- **One field table**, `src/renderer/serverFields.js`. The window draws the Pro view from it; the parser reads and
  writes the record through it; the router uses that parser. Android's copy, `ServerFieldsTable.kt`, is generated
  from it by `scripts/gen-android-server-fields.js`, and a test fails when the copy is stale.
- **A field an edit does not carry keeps its value.** The parser reads every field before it rebuilds the stream,
  then writes them back, so an edit in the Simple view never drops a Pro value. Socket options now survive any
  edit; before, an edit dropped them.
- **Subscription refresh** carries the new fields like the old ones, when the user edited them.
- **Mux for one server.** "On" muxes an eligible server without waiting for a test, even with the app's Mux off.
  "Off" never muxes it. Its own concurrency numbers replace the defaults.
- **sing-box gives VLESS Encryption to Xray.** The sing-box engine refuses a VLESS Encryption server, so the
  connect runs it on Xray instead of dialling it without encryption.
- **Android records an edit only when the user sent a field differently.** Before, a value one save derived from
  another counted as the user's: clearing a Hysteria2's port hopping also recorded its hop interval.

## How it was verified

- **The parser:** every one of the table's path fields is written, read back, kept by a Simple-view save, and
  dropped when it stops applying. A server made from scratch round-trips through its own link for every protocol. A
  share link never carries a "this device only" field. A subscription refresh keeps a Pro edit.
- **The window:**
  - its draft, field visibility, validation, labels in both languages, markup and styles have tests;
  - a real run against the app's headless server: edit in Pro, switch to Simple, rename, save; make a Trojan +
    XHTTP + TLS server from scratch; have a missing password and a bad range refused;
  - headless-Chrome screenshots of both views, dark and light, Persian and English, wide and phone width.
- **The cores:** 24 servers made from the editor's fields cover every protocol, transport and security, with every
  field set. They go through `xray run -test`: on 26.3.27 here (371 of 371 configs), and on the suggested 26.9.30
  and Xray-PattN in CI.
- **Android** compiles in CI. Its tests cover:
  - the table;
  - the generic read and write, including a Pro value kept by a Simple-view save and a transport change;
  - the Pro view's draft round trip;
  - a server made by hand for every protocol;
  - what a save refuses;
  - Mux for one server;
  - sing-box refusing VLESS Encryption.

## Not here

Protocols the Xray core does not have (TUIC, AnyTLS, Naive, SSH) are not editor fields: they would need a sing-box
engine for full configs first. The app sets a socket's interface, mark, name strategy and dialer itself (TUN binding,
entry pinning, chains), so the editor leaves them alone.
